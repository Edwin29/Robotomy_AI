# 로컬 판단 모델 비교와 비용 계획

작성일: 2026-10-17 KST. 상태: 실험 계획, 설치·다운로드·추론·플레이 실험 미실행.

RTX 4060 8GB에서 Open-Jev와 AnyJev를 한 번에 하나씩 실행해, 게임과 함께 사용할 수 있는 판단 속도와 품질을 비교한다. 목표는 추가 서비스 비용 0원이다. 사용자가 제시한 30,000원은 기존 구독료 외 추가 지출의 총 상한으로 해석하며, 월간 반복 예산으로 간주하지 않는다.

전체 경계와 관측 형식은 [게임기 설계](ai-console-design.md)를 따른다. 모델은 플레이어의 교체 가능한 구성 요소다. 게임기 자체의 영상·입력·저장에는 추론 모델이나 유료 API가 필요하지 않도록 한다.

[게임 파일 적합성 점검](lobotomy-file-compatibility-audit.md)에서 전용 덮개·스크롤 마스크·다중 카메라를 확인했다. 실제 게임 비교 자료는 이 표시 경로를 검증한 뒤 만든다. 검증 전에는 수동으로 화면과 대조한 자료 또는 합성 사례만 사용하며, 관측 추출 오류와 모델 판단 오류를 별도 집계한다.

## 비용과 Codex 구독 사용

| 항목 | 기본 계획 | 추가 서비스 비용 |
| --- | --- | --- |
| 게임기 | 로컬 캡처·가상 입력·SQLite·로컬 뷰어 | 0원 |
| 빠른 판단 | 무료로 내려받아 실행할 수 있는 공개 모델 | 호출료 0원 |
| 기억 검색 | 로컬 전문 검색·필터, 임베딩 모델 불필요 | 0원 |
| 상위 판단·개발·검토 | 사용자가 보유한 Codex Pro 5x 구독 범위에서 사용 | 새 결제 계획 없음 |
| Jev 원본 API·다른 클라우드 API·GPU 임대 | 초기 비교에서 사용하지 않음 | 0원 |
| 유료 예비비 | 사용 계획 없음 | 잔여 상한 30,000원 |

OpenAI 공식 문서상 ChatGPT 로그인은 구독 접근, API 키 로그인은 사용량 기반 접근이다. 별도 프로그램에서 OpenAI API를 호출하는 비용이 Codex 구독에 포함된다고 가정하지 않는다. 구독 한도에 도달하면 추가 크레딧·API로 자동 전환하지 않는다. [공식 인증 안내](https://learn.chatgpt.com/docs/auth), [공식 요금 안내](https://learn.chatgpt.com/docs/pricing)

Codex는 현재 연결된 도구로 상위 판단·검토를 수행하는 경로로 활용한다. 구독을 임의의 상시 HTTP 추론 서버로 바꾸거나 무제한 자동 실행을 보장하는 설계는 하지 않는다. 구독 호출 가능 여부와 별개로 게임기의 로컬 장치와 선택한 로컬 플레이어는 동작할 수 있어야 한다. 상위 모델이 응답하지 않을 때의 대기·관측·게임 대응은 플레이어 정책으로 정한다.

30,000원 예비비를 쓰지 않아도 실험이 끝나도록 범위를 정한다. 무료 경로가 느리면 먼저 후보 수·문맥 길이·모델 크기·호출 빈도를 낮춘다. 유료 서비스의 무료 체험 한도에 의존하지 않는다. 초기 실험에는 카드 등록·자동 충전·유료 엔드포인트가 없다.

로컬 추론은 전기·저장 공간·다운로드 자원을 사용하므로 총 운용비까지 0원이라는 뜻은 아니다. 추가 전기 비용을 예산에 포함할 경우 실제 또는 보수적인 시스템 소비전력 × 실험 시간 × 적용 요금으로 따로 기록한다. 요금 정보가 없으면 금액을 확정하지 않는다. 향후 유료 항목이 생기면 세금·환전·결제 수수료를 포함한 원화 비용과 미정산 예약액을 합산하며, 상한을 넘을 가능성이 있으면 실행하지 않는 예산 장치가 필요하다. 이번 문서 작성으로 그러한 장치가 구현된 것은 아니다.

## 비교 후보와 실행 방식

| 실험군 | 구성 | 목적 |
| --- | --- | --- |
| A | Open-Jev-2B 전용 로더와 공개 체크포인트 | 학습된 선택 모델의 기준선 |
| B | AnyJev Decider L0 + Qwen3-1.7B | 작은 공개 LLM의 학습 없는 선택 방식 |
| B0 | 같은 Qwen3-1.7B의 raw 선택 | 순서 편향 보정에 따른 비용·품질 비교 |
| B1 | 같은 모델의 L0 제한 회전 또는 적응 회전 | 전체 회전보다 빠르게 실행할 수 있는지 비교 |
| C 선택 실험 | AnyJev Tacit-1.7B, adaptive 비활성 | 단일 추론 방식의 대안. A/B 이후에만 고려 |
| 기준선 | 고정된 시험용 조건식과 무작위 선택 | 추론이 실제로 도움이 되는지 판별 |

Open-Jev-2B는 Qwen3.5-2B에 적용하는 LoRA와 별도 판단 헤드이며 단독 기반 모델이 아니다. 일반 텍스트 생성 로더만 사용하면 같은 모델을 시험한 것이 아니다. 공개 모델 카드의 라이선스는 Apache-2.0이며, 원본 코드와 기반 모델의 고지 역시 보존한다. [모델 카드](https://huggingface.co/ZefanCai/Open-Jev-2B)

Open-Jev 문서의 재현 시작점은 로더 커밋 `80ca8e81d08992cb2a4cbb6a0caa1355ad3e5aee`, 패키지 리비전 `0c7aa498b1627be8da4acf34c863ff0ee0a92785`, Qwen3.5-2B 기반 리비전 `15852e8c16360a2fea060d615a32b45270f8a8fc`다. 배치 1·prefix cache 비활성의 참조 경로부터 사용한다. 공개 H200 측정에는 배치 32에서 약 6.917GiB 피크가 있으므로, 배치·문맥을 줄였을 때 이 PC에 맞는지는 별도 측정 대상이다. [배포 문서](https://github.com/Zefan-Cai/Open-Jev/blob/main/docs/deployment.md)

AnyJev는 무료 공개 코드로 공개 LLM을 선택 모델로 사용하는 경로를 제공한다. 현재 문서에서 L0는 K개 선택지의 순서를 회전하며 여러 추론을 수행하고, raw는 그 보정을 하지 않는다. 최신 문서는 과거 L1/L2가 0.3.0에서 제거되었다고 명시하므로 오래된 head 예제와 현재 API를 혼합하지 않는다. [현재 방식과 버전 구분](https://github.com/nokia-applied-research/AnyJev/blob/main/docs/levels.md)

B는 [Qwen3-1.7B](https://huggingface.co/Qwen/Qwen3-1.7B)를 시작 후보로 삼되, 실행 전 AnyJev 커밋·패키지 버전·모델 리비전·라이선스·토크나이저를 고정한다. 문서의 AnyJev 명칭은 특정 기반 모델이나 모든 모델에서의 속도를 뜻하지 않는다. B1의 회전 수와 prior 설정은 별도 설정 ID로 남긴다. 실시간 배치 1 조건에서 배치 기반 prior를 무심코 사용하지 않고 content-free 등 고정 가능한 설정을 개발 세트에서 검증한다.

AnyJev의 Tacit은 별도의 학습된 체크포인트 계열이며 Decider L0와 구분한다. C의 지원 버전과 가중치 라이선스는 다운로드 전에 확인한다. 자동 reasoning 확대는 비교 첫 단계에서 끈다. [AnyJev 공식 저장소](https://github.com/nokia-applied-research/AnyJev)

### 로컬 환경과 메모리 실패 시 처리

1. WSL 2의 Linux 환경을 우선 후보로 둔다. 기존 Ubuntu를 실행하기 전에 D 드라이브 기반 모델 캐시·실험 경로와 실제 WSL 디스크 위치를 확인한다. 기존 배포판을 이동하거나 재설치하는 작업은 포함하지 않는다.
2. `.robotomy/experiments/decision-models/`를 원장·요청·결과 위치로 사용하고 모델 캐시는 D 드라이브에 둔다. 각 프로젝트의 독립 환경을 사용한다. 기존 Windows `.venv`는 유지한다.
3. 먼저 CPU에서 단일 요청과 응답 형식을 확인하고, GPU로 모델 하나를 적재한다. CUDA 호환성·정밀도·최대 메모리·실제 장치 사용을 확인한다.
4. 짧은 문맥, 동시 요청 1개, 후보 2개부터 시작한다. 추론 모델 외 GPU 사용량을 함께 기록한다. 메모리 부족이면 결과를 `does_not_fit`으로 남기고 반복 적재하지 않는다.
5. 양자화는 로더가 지원한다고 확인한 경우에만 별도 실험군으로 둔다. 일반 GGUF 파일을 Open-Jev 전용 헤드의 대체물로 취급하지 않는다. 지원되지 않으면 CPU 비교 또는 더 작은 후보로 축소한다.
6. 게임과 동시 실행할 여유가 없으면 게임 종료를 임의로 수행하지 않는다. 이후 정해진 시험 시점에 정상 종료한 조건과 게임 실행 조건을 나누어 평가한다. GPU 메모리가 부족하다는 이유로 유료 GPU로 전환하지 않는다.

## 공통 입력과 비교 공정성

입력은 동일한 관측 묶음, 목표, 질문, 후보 ID와 설명이다. 모델별 어댑터는 이 내용을 각 라이브러리 형식으로 변환할 뿐 후보를 추가·삭제하거나 정답을 보충하지 않는다. 출력은 선택 ID·후보별 점수·방식·소요 시간·모델 버전으로 정규화한다.

Open-Jev와 AnyJev가 서로 다른 기반 모델을 쓰므로 결과는 이 PC의 **배포 구성 비교**다. 순수한 알고리즘 우열로 해석하지 않는다. 같은 기반 모델 비교는 양쪽 지원과 메모리 여유가 확인된 뒤 선택 실험으로 둔다.

초기 실험은 Choice 한 종류로 제한한다. 서로 다른 Score 척도와 confidence 정의를 섞지 않는다. 모델이 반환한 0.9를 이 게임에서 90% 정답이라는 뜻으로 바로 사용하지 않는다. 추가 관찰·상위 판단 요청을 후보에 포함하고, 낮은 확신에서 어떤 후보를 선택하는지도 평가한다.

후보 생성은 플레이어의 책임이다. 첫 비교는 후보 목록을 고정해 선택기만 측정하고, 이후 별도 단계에서 LLM이 후보를 생성하게 한다. 후보 생성 지연도 전체 반응 시간에 포함한다. 개발자가 작성한 기준선의 조건은 시험용 지시이며, 경험으로 배운 게임 전략과 구분한다.

## 자료 구성

초기 자료 목표는 독립 사례 180개, 유형별 30개다. 튜토리얼 기록만으로 수가 부족하면 합성 UI·입력 사례를 추가하되 실제 게임 관측과 별도 집계한다. 수량을 채우려고 동일 프레임을 복제해 독립 사례로 세지 않는다.

| 유형 | 확인할 능력 |
| --- | --- |
| 표시 정보 변화 | 주어진 목표에 맞는 후보 선택 |
| 가림·오래된 관측 | 보이지 않는 값을 현재 사실로 사용하지 않기 |
| 모순·불확실성 | 추가 관찰 또는 상위 판단 요청 |
| 입력과 결과 구분 | 입력 적용만으로 작업 성공을 확정하지 않기 |
| 소리와 시간 순서 | 제공된 사건 순서와 경험만 이용하기 |
| 후보·질문 변화 | 순서·표현·질문이 바뀌어도 조건에 맞게 판단하기 |

각 사례는 원본 근거, 허용 관측, 질문, 후보, 허용 답 집합 또는 평가 기준, 라벨 작성 근거를 가진다. 유일한 전략적 정답을 알 수 없는 경우 다중 허용 답이나 정성 평가로 남기고 정확도 분모에서 분리한다. 정답이 없는 전략 문제를 임의 라벨로 단정하지 않는다.

60개 개발·60개 보정·60개 최종 시험으로 나눈다. 같은 에피소드의 인접 프레임, 가림 반사실 쌍, 순서 변경 변형은 같은 분할에 둔다. 충분한 독립 에피소드가 없으면 시험 세트가 제한적이라고 보고하고 이후 신규 세션으로 검증한다. 최종 시험을 본 뒤 바꾼 설정은 같은 시험의 사전 고정 결과로 발표하지 않는다.

기존 live JSON은 가림 검증이 불완전하므로 그대로 정답 관측으로 쓰지 않는다. 먼저 대응 화면에서 확인되는 내용만 선별한다. 새 추출기가 만들어지기 전 자료는 수동 검토 또는 합성이라는 출처를 남긴다. 공략·게임 내부 코드·미공개 규칙은 입력과 라벨 근거에서 제외한다.

후보 순서 원본·역순·고정 seed 순열 2개를 사용해 선택 변경률을 비교한다. 같은 변형들의 통계적 독립성을 가정하지 않는다. 한국어를 주 실험 언어로 사용하고, 영어 번역은 동일 사례의 별도 실험으로 분리해 번역 비용과 정보 차이를 기록한다.

## 실행 단계와 측정

### 1단계 설치 가능성과 메모리

모델별 단일 요청 10개로 실제 체크포인트·장치 사용·응답 유효성을 확인한다. import 성공이나 CPU 모의 서버 성공을 GPU 모델 추론 성공으로 보고하지 않는다. 첫 실행 최대 15분, 같은 오류 재시도 최대 1회로 제한하는 안을 둔다. 이 단계 실패 시 종속 성능 시험은 생략한다.

### 2단계 오프라인 판단 품질

개발 세트에서 입력 형식과 후보 설명을 고정하고, 보정 세트에서 기권·상위 모델 요청의 임계값을 고른다. 최종 시험에서는 설정을 고정한다. 모델별 전체 정확도 외에 유형별 오류, 관측 범위 위반, 기권률, 자동 선택한 사례의 오류율, 후보 순서 민감도를 기록한다.

작은 시험 세트의 오류 0건은 오류율 0% 보증이 아니다. 사례·에피소드 단위의 분모와 구간 추정을 함께 제공한다. Brier score와 보정 구간별 관측 정확도를 참고하되 작은 세트의 ECE 하나로 모델을 선정하지 않는다.

### 3단계 지연과 부하

- 내용 길이 3구간: 기준 토크나이저로 약 128·512·1,024토큰. 두 모델에는 같은 원문을 주고 각자의 실제 토큰 수도 기록한다.
- 후보 수 2·4·8개. 32개는 선택적 스트레스 시험이며 기본 실시간 사용 조건이 아니다.
- 문맥 길이 × 후보 수의 9조건, 조건별 준비 호출 5회 후 측정 50회로 시작한다. 대표 조건은 200회로 확대한다.
- 준비 호출은 지연 통계에서 제외하고 실패·타임아웃은 별도 포함 집계한다. 냉간 모델 로딩은 따로 보고한다.
- 동시 요청 1개, 서로 다른 상태를 반복해 동일 요청 캐시의 착시를 피한다. 모델 순서는 A/B, B/A로 번갈아 시험하고 같은 부하 조건을 사용한다.
- 모델별 요청 상한 5,000회, 전체 초기 실험 최대 10시간으로 둔다. 한 요청이 5초를 넘으면 실시간 후보에서는 시간 초과로 집계한다. 원인 분석을 위한 더 긴 실행은 별도 조건이다.

측정 항목은 전처리, 토큰화, 추론, 응답 변환, 로컬 왕복 P50/P95/최댓값, 기한 초과, GPU/RAM 피크다. GPU 내부 시간은 동기화해 측정하고, 실제 사용자 지연은 같은 호스트의 단조 시계로 별도 측정한다. 처리량의 평균 ms/건을 단일 요청 지연으로 대신하지 않는다.

AnyJev는 실제 회전 수·추론 횟수·prior·방식과 부가 준비 시간을 남긴다. Open-Jev는 후보 배치 설정·캐시·정밀도를 남긴다. 보정 비용은 준비 비용으로 분리하되 전체 운용비와 최초 준비 시간에 포함한다.

공개 H100 결과는 성능 목표를 보장하지 않는다. Open-Jev의 공개 측정도 문맥·후보 수에 따라 지연이 크게 달라진다. 이 PC의 새 결과를 사용한다. [공개 측정 조건](https://github.com/Zefan-Cai/Open-Jev/blob/main/docs/inference-latency.md)

### 4단계 게임과 동시 실행

관측·입력 장치가 구현·검증된 뒤 진행한다. 게임만 실행, 게임+관측, 게임+관측+모델 조건을 각 3회·5분씩 같은 장면에서 비교한다. 가능한 범위에서 창 크기·게임 배속·녹화 설정·백그라운드 부하를 고정하고 GPU 메모리를 재확인한다.

평균 FPS만 보지 않고 프레임 시간 P95/P99, 캡처 누락, 관측 나이, 입력 적용 지연을 기록한다. 게임 프레임 시간 P95가 기준보다 10% 이상 나빠지거나 메모리 부족·입력 해제 실패가 발생하면 동시 실행 설정을 불합격으로 두고 축소한다. 10%는 초기 허용 기준이며 실제 장면의 요구에 따라 조정할 수 있다.

### 5단계 제한된 실제 플레이

먼저 입력 권한 없는 shadow 모드로 후보 선택을 기록한다. 이 결과는 실제 행동 성공률로 보고하지 않는다. 이후 원본 저장 보호와 입력 수용 검증을 통과한 별도 세이브에서 회당 최대 5분·입력 30회, 모델별 최대 3회로 시작한다.

동일한 시험용 시작 상태를 확보할 수 있을 때만 짝지은 플레이 비교를 한다. 현재 자동 세이브 복원이 구현되어 있다고 가정하지 않는다. 시작 상태가 달라지면 조건 차이를 기록한다. 진행도·손실·잘못된 반복·기한 초과·사람 개입을 함께 보고한다. 정지가 가능한 게임 조건과 불가능한 조건은 따로 평가한다.

## 선정 기준과 실패 시 대안

빠른 경로의 초기 후보 조건은 짧은 상태·후보 4개에서 로컬 요청 P95 200ms 이내, 기한 초과 1% 이하, 검증 자료의 공개 범위 위반 0건이다. 전체 게임 반응 시간과 자동 선택의 오류율을 함께 확인한다. 표본이 적으면 합격을 확정하지 않고 다음 시험으로 넘길 후보로만 분류한다.

보정 세트에서 자동 선택 오류율 5% 이하를 목표로 기권 임계값을 고르고, 최종 시험에서는 기권률과 오류율을 함께 보고한다. 자동 선택을 거의 하지 않는 모델이 안전해 보이는 착시를 막기 위해 coverage를 반드시 표시한다. 이 기준은 일반 선택기의 초안이며 치명적인 게임 행동의 허용 오류율을 대신하지 않는다.

- **둘 다 만족:** 품질과 지연의 상충 관계를 보고 플레이어가 사용할 기본 모델을 선택한다. 모델 이름만으로 승자를 정하지 않는다.
- **품질은 좋고 느림:** 빠른 반사 경로 대신 중간 속도 판단에 배치한다.
- **둘 다 품질 부족:** 플레이어가 경험으로 만든 제한된 정책과 상위 LLM을 사용하고, 실패 사례를 추가한다. 공략을 넣어 점수를 높이지 않는다.
- **GPU 동시 실행 불가:** 작은 모델·짧은 문맥·CPU의 낮은 빈도 실행을 검토한다. 구독 상위 판단은 활용할 수 있지만 초 단위 반응을 보장하지 않는다.
- **비전이 필요한 실패:** 해당 장면만 소형 비전 모델 실험으로 확장한다. 구조화된 값으로 화면 가림을 우회하지 않는다.

## 결과와 재현 자료

실험별로 `manifest.json`, `requests.jsonl`, `responses.jsonl`, `timings.jsonl`, `errors.jsonl`, `report.md`를 남기는 형식을 제안한다. manifest에는 소스 커밋·가중치 리비전·해시·정밀도·실행 장치·라이브러리 잠금 목록·OS/드라이버·seed·자료 분할·게임 부하·예산을 포함한다.

결과표에는 다음 열을 둔다: 구성 ID, 자료 출처, 품질 분모, 정확도/허용 답 일치, 자동 선택 비율과 오류율, 순서 변경률, P50/P95, 타임아웃 수, VRAM/RAM 피크, 게임 프레임 영향, 추가 비용, 미통과 항목.

원본 요청·응답과 실패를 보존한다. Git에는 검토한 보고서와 작은 재현 목록만 넣고 가중치·게임 자산·세이브·대용량 미디어는 넣지 않는다. 모델 이전 효과는 별도 실험에서 기억 없음·요약·사건 연결 기억을 비교하며, 이번 선택기 비교 결과만으로 디지털 트윈이나 경험 이전이 검증되었다고 하지 않는다.
