# 실시간 관찰·실행 v2 — 개발 후보

2026-10-20. 이 문서는 개발/검증용이다. 본 플레이 게임과 MCP에는 아직 배포하지 않았다.
새 모델·유료 API·영상 인식 서버를 추가하지 않는다.

## 변경한 흐름

게임의 최종 표시 → 기존 공개 정보 필터 → 공통 플레이어 상태 → ID별 변경분 → MCP 반환/경험 기록.
입력 결과도 같은 상태 비교기를 사용한다. 내부적으로 확인했지만 반환하지 않은 중간 화면은
비교 기준이나 플레이어의 관찰 기록으로 취급하지 않는다.

- `perception.py`: 직원·엔티티·시설을 키별로 비교한다. 구조화 창과 원문 UI의 중복을 줄인다.
  위험 변경은 `priority_changes`, 나머지는 `changes`로 분리하고 동일 변경을 양쪽에 넣지 않는다.
  지도는 `known_map.landmarks`, 현재 관찰은 `facilities`다. 화면 밖 항목은 현재 관찰에서 제거된다.
- `ConsoleSignals.cs`: 직원/엔티티의 관찰용 ID를 임시 입력 토큰과 분리한다.
  ID는 게임 세션/장면/하루 경계에서 초기화된다. 보이지 않는 위치나 상태를 유지하지 않는다.
- 소리는 인접한 동일 사건만 묶는다. 재생→중단→재생 순서를 보존한다.
  source_idle/source_destroyed를 가청 정지로 해석해 전달하지 않는다.
- `realtime.py`: 100ms 간격으로 공개 관찰을 읽고 사건 512개를 보관한다.
  원본 UI 신호는 게임 안에서 최근 128개를 보관하므로 MCP 도구 호출 간 짧은 사건도 회수할 수 있다.
  버퍼 초과는 gap으로 알린다. 사건은 journal_id와 id의 쌍으로 구분한다.
- `wait_for_event`: 최대 20초의 사건 대기 및 커서 조회. `cancel_event_wait`로 취소한다.
  모델 추론 도중 강제로 메시지를 주입하는 기능은 아니다.
- `execute_intents`: 지정된 work/move/input 1~5개를 실행한다. 계획·대상·작업 종류를 임의로 바꾸지 않는다.
  내부 단계의 영수증과 마지막 관찰을 반환한다. 10초가 지나면 새 의도를 시작하지 않지만,
  실행 중인 bounded 입력/확인은 종료까지 더 걸릴 수 있다.
- `view_region`: 현재 캡처의 지정 부분을 자른다. 원본 화면 밖 정보는 얻지 않는다.
  전체 화면 도구는 스토리·연출·새 장면에 계속 사용한다. Pillow는 로컬 이미지 처리만 담당한다.
- `reload_host.py`: 도구 처리 시간, 응답 텍스트 크기, 이전 응답과 다음 요청 간격을 별도 로그로 기록한다.
  이미지 base64를 텍스트 토큰으로 계산하지 않는다. 텍스트 토큰 추정치는 실제 과금 사용량이 아니다.
  요청 간격에는 모델·호스트·사용자 대기가 섞여 있어 추론 시간이라고 단정할 수 없다.

## 일회용 정지 예약

기본 비활성이다. 플레이어가 등록한 조건만 감시하고, 기본 슬롯은 1개다.
운영자가 `.robotomy/live/operator-policy.json`에 `{"pause_slots":2}`를 설정하면 2개까지 가능하다.
플레이어 MCP에는 슬롯 수를 변경하는 도구가 없다.

| 조건 | 근거 |
|---|---|
| meltdown_cycle | 게이지를 채워 공통 폭주 안내가 실제 표시됨. 격리실 폭주와 시련 주기를 함께 포괄 |
| employee_death | 기존 공개 사망 명단에서 새 사망이 확인됨. 카메라 밖 위치/원인은 추가하지 않음 |
| escape_confirmed | 게임의 탈출 알림이 실제 ConversationUI에 표시되고 글자가 공개됨 |

발동 시 예약은 먼저 소모되고 남은 입력을 차단한다. 입력 잠금을 획득한 뒤 정지를 한 번 시도한다.
이미 정지 중이면 입력하지 않는다. 실행 직전에도 Unity의 실제 입력 조회 시점에서
`GameState.PLAYING`일 때만 Space를 제공하는 `pause_only` 키를 쓴다.
따라서 관찰과 입력 사이에 정지 상태가 바뀌어도 자동 정지가 재생 토글로 바뀌지 않는다.
실제 게임의 Space 처리 경로를 유지하므로 정지 제한/패널 차단을 우회하지 않는다.

실패해도 예약은 소모된 상태다. 자동 재시도·자동 재활성화는 없다.
장면/프로세스/게임 세션/하루 시작 경계, MCP 종료·코드 재로딩에서는 예약을 해제한다.
탈출 알림이 게임 설정/연출 때문에 표시되지 않는 경우까지 탐지한다고 보장하지 않는다.
보스별 모든 정지 제한 및 왜곡 장면을 실기로 검증한 것은 아니다.

## 게임 파일에서 확인한 연결

게임 코드 분석 산출물 자체와 게임 DLL은 Git에 포함하지 않는다.

- `CreatureOverloadManager.AddOverloadGague` → 임계치 도달 →
  parameterless `ActivateOverload`: 시련 또는 격리실 폭주 처리 후
  `EnergyController.SetOverLoadUI` 호출, 게이지 0으로 초기화.
  따라서 max 수치를 폴링하거나 방별 타이머만 보는 방식은 사용하지 않는다.
- `EnergyController.SetOverLoadUI` → OverloadUIController 활성화, 공개 안내 Text/연출.
  훅 호출만으로 사건을 내보내지 않고 실제 Text 가시성을 확인한다.
- `SefiraConversationController.OnNotice(NoticeName.OnEscape)` →
  `UpdateConversation` → `ConversationUI.InitUI` → 공개 InnerText.
  내부 탈출 대상/경로/타이머를 별도로 내보내지 않는다.
- `PlaySpeedSettingUI.Update`의 Space 분기는 `_available`, 정지 제한,
  관찰 상태 등을 확인한 후 Pause/Resume을 선택한다. 이를 직접 상태 변경으로 대체하지 않는다.

  09:05:12.402 UTC 사건 관찰 → 09:05:13.089 UTC 정지 확인, 약 0.69초.

  문자 수이며 모델 판단 시간/토큰 과금의 감소율이 아니다.
- 실제 Lab 표본 40개의 delta를 순서대로 적용한 상태와
  동일 표본의 전체 플레이어 상태가 일치했다.
- 최종 DLL에서 pause_only를 실행 중 1회, 정지 중 2회 전송했다. 결과는 모두 paused로 유지됐다.
  부분 캡처 도구도 실제 320×180 이미지 반환을 확인했다.
- 작업 중인 방에 재배정하려는 batch는 종속 단계를 중단했다.
  이미 선택된 배속 버튼은 조작 가능 대상으로 취급하지 않았다.
- 사망/탈출 조건의 일회 소모, 기존 사건 재사용 금지, 슬롯 제한,
  장면 전환 해제, 대기 취소는 fixture로 검증했다.
  사망·탈출을 자연 발생시켜 모든 종류를 실기로 시험한 것은 아니다.

로컬 상세 증거: 개발 사본의 `.robotomy/lab-verification/`.
검증 중 임의로 플레이어 경험 시도를 만들지 않았다. background 사건 로그는 공학 자료이며
실제로 반환된 경험과 분리한다.

## 배포 순서와 되돌리기

아래는 배포 준비 당시 절차다. 2026-10-20 본 플레이 배포를 완료했다. 활성 MCP는 원본 소스를 자동 재로딩하므로
게임 진행 중 원본 소스에 파일을 덮어쓰지 않는다.

1. 안전한 저장 지점 확인 후 본 플레이 MCP를 종료한다. 현재 게임/원본 세이브 무결성과 백업을 확인한다.
2. 해당 후보의 Python 소스·의존성·플레이어 문서를 함께 반영한다.
3. 본 플레이 게임을 정상 종료한 상태에서 production 후보 Observer DLL을 반영하고 manifest 해시를 갱신한다.
4. 공식 격리 런처로 실행한다. MCP는 새 카탈로그로 재연결하고 플레이어는 안내를 다시 읽는다.
5. compact full 기준, 단일 입력 후 delta 기준 연결, 예약 없음, 가상 입력/격리 저장 경로를 확인한다.

이 변경은 도구 카탈로그와 상주 입력 모듈, DLL이 함께 바뀌므로 코드 hot reload만으로 배포하지 않는다.
문제가 생기면 저장 데이터를 바꾸지 않고 이전 Python/DLL/문서/manifest를 함께 복구한다.
구형 current 및 section diff를 기대하는 소비자에는 v2 계약 변경을 먼저 반영해야 한다.
