## 실제 파일 분석
REA 정적 메타데이터 증거: ev_5c34c73bd3f17756da3230dbb1e750da2754bca3704fe85556f6a960f1c81fb4 및 ev_7ff2f7a051f1115e3340871a527e2b00b2d544c79bb10888ff7eb17a38156d4d. 로컬 ILSpy로 두 DLL 전체를 확인했다. 기존 BaseMod와 Harmony 및 게임 어셈블리만 참조한다. 원본과 격리 게임 Assembly-CSharp SHA256이 동일함도 확인했다.

천장 모드는 GetProb, SetProb, FinishWorkSuccessfully, StartStage, EndGame에 패치한다. Settings.txt의 기존 0.25 0.75 1을 그대로 복사했다. 나쁨/보통/좋음에 해당하며 기프트 미획득 때 기본 확률에 곱하는 배율의 증가량이다(퍼센트포인트 가산이 아님). 해당 환상체 기프트를 이미 보유했거나 잠금으로 획득할 수 없으면 누적하지 않는다. 획득 시 해당 누적 삭제, StartStage/EndGame 시 전체 삭제, 확률 상한 1.0. UI 확률 표시는 소수 1자리로 바뀐다. 이 버전은 작업 완료 메서드를 통째로 대체한다. 기존 경험치 계산 경로를 비교했고 마지막 CancelWork는 현재 게임에서 CloseWork(false)로 들어가지만 해당 success 인자는 본문에서 사용되지 않아 완료 처리 차이가 없는 것을 확인했다. 향후 게임/다른 모드가 이 메서드를 바꾸면 재검토가 필요하다.

정규직 모드는 NewTitleScript.OnClickNewGame과 AlterTitleController.CallNewgame에 패치한다. 마지막 저장의 agentList를 불러와 직원 장비/기프트를 포함한 직원 LoadData를 거쳐 대기 인원에 넣고 부서 배치를 해제한다. 아직 저장되지 않은 현재 운영 진행을 보존하는 기능으로 해석하면 안 된다. 기억저장소 경로는 패치하지 않는다.

BaseMod 로더는 목록 XML에 없는 디렉터리도 자동 로딩한다. 다른 모드를 활성화하는 원본 BaseModList_v2.xml은 복사하지 않았다. DLL/메타데이터/천장 설정만 포함된 두 폴더를 원본과 해시 비교했다.

검증용 게임 런타임에서 Harmony owner별 실제 등록 메서드가 천장 5개, 정규직 2개임을 확인했다. 설정 배열 0.25,0.75,1도 확인했다. 증거: Robotomy_Lab/.robotomy/live/modcheck.txt. 진단 코드는 검증용에서만 사용했고 종료 후 일반 Observer로 복구했다. 본게임에 진단 DLL을 넣지 않았다.
