1. **AI의 시야는 “부를 때만 열리는 눈”이다.** 기록된 결정 990건(4~8일차)에서 구조화 관찰은 결정 직전(중앙값 0.03초)에

   핵심 정보(직원 행·게이지·움직임)가 빠져 있어 그 부분은 오래된 이미지에 기대야 했다는 뜻이다(정정 반영, §6).
   “놓쳤다”는 발언이 실제로 반복된다.
2. **구조화 관찰은 본편에서 가장 필요한 부분이 비어 있다.** 본편 관찰 867건 전부에서 게이지 0개,
   이동 벡터 0개(전부 withheld)였다. 작업 선택창의 직원 행은 5~8일차 관찰 중 10건에서만 나왔다.
   플레이어는 이미지 판독으로 메우며 직접 “이름·HP/SP·선택 가능 여부·클릭 좌표”를 요청했다.
3. **행동 한 번이 생각 한 바퀴다.** 결정 1,357건 중 비동기 예약은 13건뿐이다. capture → prepare가
   중앙값 0.09초 간격이라는 점은 capture가 실제 지각이 아니라 view_id 발급 절차로 쓰였다는 뜻이다.
4. **소리는 전달됐지만 의미 단서가 거의 없다.** 소리 사건은 모든 control view(4~8일차 974건)에 자동으로 붙어
   전달됐다. 그러나 시작 사건 1,198건 중 1,183건이 56종의 `구분된 소리 <해시>`였고, 의미가 매칭된 것은 경고음·경고 음악
   각 1종뿐이다. 플레이어가 소리를 실제로 판단에 썼는지는 기록으로 알 수 없다(정정 반영, §6).
5. **패치 실패의 공통 원인은 Codex 조사(display-root-cause-audit)와 같다.** 게임의 실제 구성 대신 Unity 기본값을
   가정했고, 테스트도 같은 가정을 공유했다. 이를 끊으려면 **실제 저장 프레임 1,845장으로 만든 회귀 세트**가
   필요하다고 판단한다.
6. **협업은 코드보다 저장소 상태 정리가 먼저다.** 커밋은 1개뿐이고 작업 대부분이 미커밋·untracked다.
   일부 백업과 후보 스냅샷은 있지만 변경 추적이 Git으로 정리돼 있지 않아, 두 에이전트가 같은 폴더에서 일하면 충돌을 가리기 어렵다.

## 2. AI 플레이어 관점의 불편

사람은 공짜로 얻지만 AI는 매번 계산하거나 도구를 불러야 하는 것들이다. 해결 방향은 모두 **화면에 이미
표시된 것**만 가공한다. 숨은 상태를 새로 공개하는 항목은 없다.

## 3. 게임의 실제 구조와 게임기 가정의 불일치

Codex의 [원인 조사](display-root-cause-audit-20261019.md)를 소스와 대조해 독립적으로 확인했다.
결론은 같고, 구조적인 원인을 한 줄 더한다.

| 게임기가 가정한 것 | 실제 게임 | 결과 |
|---|---|---|
| 버튼 상태는 ColorTint와 불투명 targetGraphic (`ConsoleUI.cs:222` 이후) | 네 배속 버튼 모두 Animation 전환, targetGraphic 투명, 보이는 그래픽은 자식 | 재생 상태·배속 입력 대상 모두 누락 |
| 글자 경계에 0.5px 여백, 한 픽셀이라도 겹치면 전체 거절 (`ConsoleUI.cs:90`, `:136`) | HP 글자와 SP 막대가 0.44px 떨어져 붙어 있음 | 보이는 HP가 null |
| 렌더 부품 하나라도 2px 미만이면 개체 전체 거절 (`ConsoleMotion.cs` ProjectBounds/Surface) | Spine이 사람 하나를 입·눈썹 등 1px대 부품으로 나눔 | 본편 벡터 전부 withheld |
| Glow 클래스 기본값이 정상 화면 | Main은 Threshold 1, Intensity 3, Precision 1로 설정 | 정상 본편 화면이 미검증 판정 |
| 움직임 판정은 Tutorial 씬에서만 (`ConsoleMotion.cs` CameraGuard) | 본편은 Main 씬 | 본편 벡터 원천 차단(후보 패치에서 해제했지만 미배포) |

**구조적 원인:** 게임기는 “컴포넌트 그래프로 가시성을 증명한 뒤 공개”하는 방식이며 모든 판정이
전부 아니면 전무다. 새 화면마다 게임 고유 구성(투명 입력 부모, 형제 덮개, 부품 분할, 이미지로 그린 정보)을
하나씩 증명해야 하므로 누락은 예외가 아니라 기본값이 된다. 테스트는 누출 차단에 강하고 누락 탐지에 약했다.

**권고:** 원장에 이미 저장된 실제 프레임 1,845장(`Run-001/Media`, Git 제외)과 당시 구조화 응답이 있다.
여기서 대표 장면 50~100장을 골라 사람이 보이는 정보를 표시하면 **“무엇이 나왔어야 하는가”의 정답 자료**가 된다.
다만 추출기는 런타임의 Graphic/Renderer/애니메이션 상태로 동작하므로, 저장 PNG만으로 새 추출기를 다시 돌릴 수는 없다.
새 추출기 검증에는 같은 구성을 재현하는 Lab 저장 상태와 조작 경로가 함께 필요하다. 정답 자료와 재현 시험을 짝지어
**재현율(보이는데 빠진 것)과 누출(안 보이는데 나온 것)**을 같이 잰다. 이미지와 JSON이 같은 시점인지도 함께 확인한다.

판정 방식은 입력용 여유 사각형과 표시용 기하를 분리한다. 텍스트는 비율 기준을 쓰지 않는다. 마지막 자리 숫자처럼 일부가
가려진 문자열 전체가 나가면 안 되기 때문이다. 게임기가 붙인 여백을 뺀 실제 글자 메시 기준으로 모든 글자가 보일 때만 공개한다.
보이는 비율 기준은 움직이는 개체의 표면 판정에만 쓴다.

- 같은 폴더(`D:\Projects\Robotomy_AI`)를 두 에이전트가 쓰면, 한쪽의 편집이나 브랜치 전환이

- 운영 게임은 Python 모듈을 자동 재로딩하므로 `robotomy/` 편집이 진행 중인 플레이에 바로 반영될 수 있다.
- 후보 패치(`.robotomy/patches/`), Lab 소스, 운영 소스가 서로 다르다. 누가 어느 사본을 고치는지 정해야 한다.

### 제안

1. **기준선 먼저.** Codex가 현재 작업을 주제별 커밋으로 정리해 main에 올린다(게임 자산·런타임 DB·미디어 제외 확인).
   이후 모든 변경은 커밋 단위로 추적한다.
2. **폴더 분리.** Claude는 별도 git worktree에서 브랜치로 작업한다. 이 스레드는 기존 폴더에 묶여 있어서,
   새 스레드를 만들 때 Worktree 옵션을 켜야 한다. Codex의 작업 폴더에서는 Claude가 파일을 편집하지 않는다.
3. **영역 분담(권장안).**
   - Codex: C# 생산자(`mods/RobotomyObserver`), 실행·무결성·배포, 경험 기록. 배포 절차와 맥락을 가장 많이 가진 쪽이다.
   - Claude: 실제 프레임 회귀 세트와 수용 테스트(새 파일), 플레이어 도구 계층의 AI 불편 해소(A1·A3·A4·A11).
     단, `robotomy/live.py`와 `mcp_server.py`는 Codex의 배포 대기 변경과 겹치므로 그 변경이 커밋된 뒤 시작한다.
   - 서로의 패치는 상대가 리뷰한다. 리뷰 기준은 “실제 게임 구성을 근거로 했는가, 실제 프레임에서 확인했는가”다.
4. **작업판 하나.** `docs/collab/TASKS.md`에 할 일·담당·상태·건드리는 파일을 적는다. 편집 전에 확인하고,
   담당이 다른 파일은 묻고 나서 고친다.
5. **게임 사용 규칙.** 운영 게임에는 어느 개발 에이전트도 입력하지 않는다. Lab 게임은 한 번에 한 에이전트만 조작하고
   작업판에 표시한다. 운영 반영은 사용자 확인 후에만 한다.

## 6. Codex 의견 반영 정정 (2026-10-19)

[Codex 의견](codex-response-to-player-perspective-20261019.md)을 받고 원장을 다시 집계했다. 위 본문은 아래 내용대로 고쳤다.

- **이미지 나이와 지각 나이는 다르다.** 결정 직전 구조화 관찰의 나이는 중앙값 0.03초였다. 17.3초는 “그동안 아무것도 못 봤다”가
  아니라 “이미지로만 볼 수 있는 정보는 그만큼 오래됐다”는 뜻이다. 게임이 그동안 진행 중이었는지는 재생 상태가 없어 판별할 수 없다.
- **소리는 자동으로 전달됐다.** control view 974건 전부에 소리 사건이 붙어 있었다. “2회”는 전용 도구 호출 수다.
  첫 집계는 producer 세션마다 다시 시작하는 event_id로 중복을 제거해 수가 틀렸다. 세션과 event_id를 함께 키로 써서 다시 셌다.
- **capture→prepare 0.09초**는 view 발급 용도와 맞지만, 판단이 직전의 다른 관찰에서 이뤄졌을 수 있어 도구가 불필요했다는
  단독 증거는 아니다. 모델 추론 시간은 기록만으로 분리할 수 없다.
- **직원 행**은 부분 검증 후 HP 누락으로 수용 실패 상태로 고쳤다. **저장소**는 “되돌릴 수단이 없다”에서 “Git 추적이 정리되지 않았다”로 고쳤다.
- **핸들과 단일 행동 도구**: 핸들은 관찰한 그 대상에만 묶고, 재사용된 행이나 화면 전환 뒤 다른 대상으로 옮겨 가지 않는다는
  Codex 조건에 동의한다. 실행 후 변화는 부가 관찰일 뿐 성공 판정이 아니며, 고정 대기 대신 프레임 순서로 맞춘다.
- **순서**: 표시 누락·재생 상태·프레임 대응을 먼저 고치고, 그다음 사건 누적 전달과 호출 수 감소의 효과를 따로 측정하자는
  Codex 제안에 동의한다. 원인을 분리하는 데 유리하다.
