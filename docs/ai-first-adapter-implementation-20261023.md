### 관찰과 조작

- `player_view_v1`: `alerts`, `combat`, `updated`, `left_view`, `action`, `audio` 위치를 통일했다.
- 변경된 직원/엔티티는 현재 행으로 반환한다. 목록에서 사라짐은 `no_longer_observed`이며 사망으로 추정하지 않는다.
- 고정 지도/본문/화면 UI는 변경 시 제공한다. 화면상 직원 위치·속도는 소수점 한 자리, 막대 비율은 두 자리로 정리한다.
  원래 정밀도의 관찰 도구는 계속 사용할 수 있다. 화면에 숫자가 없는 막대를 내부 HP로 대체하지 않는다.
- `unit:` 참조를 선택·이동·작업 배정에 공통으로 사용한다. 작업창이 열려 있으면 해당 직원 행을,
  이동 명령은 화면 직원을 선택한다. 실행 직전에 기존 게임기 입력 경로에서 대상을 재확인한다.
- 플레이어 입력은 `[L/R/H, 대상]`, `[K, 키]`, `[Z, 확대·축소]`, 직원 이동·작업의 명시적 객체다.
  내부 목적지나 작업 상태를 직접 덮어쓰지 않는다.
- 일시정지/배속/기프트 잠금은 원하는 값을 받으며 이미 맞으면 입력하지 않는다.
  배속 설명창이 이웃 버튼을 가리면 가상 포인터를 옮겨 다시 조회한다. 보이지 않는 버튼을 맹목 클릭하지 않는다.
- `request_id`를 재사용하면 결과가 불명확했어도 다시 입력하지 않는다. 같은 ID의 다른 요청은 거절한다.
- 입력 결과에 같은 관찰 형식을 함께 반환한다. `input_sent`, `ui=ready`, 도착/작업 완료는 구분한다.
  자세한 실행 기록은 로컬 trace 파일로 분리한다.
- 1~5개, 최대 10초 예약은 동일 명령 문법을 사용한다. 중간 취소, 장면/화면 크기 변경,
  대상 소실, 실패, 일시정지 예약의 세대 변경에 중단한다. 메뉴가 바뀌어도 다음 대상이 현재 유효하면 진행한다.
  실행된 입력을 취소로 되돌리지는 않는다. 관찰 응답은 미확인 예약 결과의 ID도 알려준다.
- 대상 확대는 현재 프레임과 해당 프레임의 좌표를 해시로 연결한다. 보관된 이전 프레임은 최대 6개까지
  시각별로 반환한다. 현재 좌표를 과거 이미지에 적용하지 않는다.
- 내부 상태 스냅샷을 응답 생성 시 고정하여 다른 호출의 상태와 관찰 ID가 섞이지 않도록 했다.
  중간 포인터 이동/예약 실행 자료를 실제로 반환한 관찰인 것처럼 기록하지 않는다.
