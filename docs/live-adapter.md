# 다음 단계: 실제 Lobotomy 연결

**미구현. 이 문서는 실행 가능한 모드나 확인된 게임 API 목록이 아니다.**

## 현재 근거

지정된 설치 경로에서 LobotomyCorp.exe, Managed/Assembly-CSharp.dll,
0Harmony.dll, LobotomyBaseModLib.dll 존재를 다시 확인했다.
파일 존재는 모드 로더 호환성/정상 실행을 증명하지 않는다. 기존 모드·진행·세이브 위치는
다음 작업에서 읽기 전용으로 확인해야 한다. 이 레포에는 게임 파일을 복사하지 않았다.

## 첫 연결 작업

1. 현재 로더/게임 버전과 세이브 위치를 확인한다. 기존 상태를 해시와 함께 기록한다.
2. 배포 파일 목록·백업·복구 절차를 확정하고 테스트 프로필/세이브를 준비한다.
3. 작은 읽기 전용 연결 모드로 UI와 같은 정보를 출력한다. 다른 모드가 이미 있다면 호환성을 점검한다.
4. 같은 시점의 화면과 관찰 값을 대조한다. 숨겨진 성공률·미해금 설명·내부 타이머가 새지 않는지 확인한다.
5. 정상 UI가 허용하는 단일 명령만 연결한다. 대상 유효성, 현재 상황, 게임 제약을 우회하지 않는다.
6. 실패/오래된 관찰/중복 요청/연결 끊김을 검사한 뒤 짧은 플레이로 넓힌다.

## 연결 인터페이스 초안

모드와 로컬 실행기 사이에 다음 메시지를 둔다. 전송 방식은 코드 분석 후 결정한다.

- `capabilities`: 관찰/행동 목록, 게임·모드 버전, 공개 정보 정책 버전
- `observation`: scene ID, revision, 게임 시간, 화면/정상 UI로 알 수 있는 객체와 사건
- `command`: 고유 command ID, decision ID, 근거 observation ID, 대상 ID, 행동, 만료 조건
- `receipt`: accepted / applied / rejected / unknown, 결과 observation ID
- `events`: 작업 완료/새 화면/위험 알림 등 플레이어에게 보이는 변화

Unity 상태 접근과 명령 적용은 해당 런타임의 메인 스레드 규칙을 따라야 한다.
재시도 시 command ID로 처리 결과를 확인한다. 응답이 없다고 같은 명령을 새 ID로 재발행하지 않는다.
실제 적용 여부가 unknown이면 상태를 대조해 복구한다. 합성 테스트의 SQLite 원자성을 실게임에
그대로 적용할 수 있다고 가정하지 않는다.

## 합격 기준

- 실제 화면과 구조화 관찰이 맞는다는 증거
- 정상 플레이어가 아직 모르는 정보를 노출하지 않는다는 검토
- 하나의 판단 ID → 명령 ID → 실제 결과 연결
- 잘못된 대상/상태가 바뀐 명령/중복 명령 거부 또는 안전한 결과 재조회
- 사람의 중지 후 새 명령이 적용되지 않는지 확인; 이미 적용된 명령과 구별
- 연결 종료/재시작 및 기존 게임/세이브로 복구 확인
- 실제 플레이의 관찰 기록과 합성 예제가 섞이지 않음

게임 바이너리 디컴파일/숨은 규칙은 개발자 채팅에만 둔다. 플레이어 프롬프트와 경험 번들에
개발자 조사 결과를 넣지 않는다. 기존 플레이 세이브를 승인 없이 초기화하지 않는다.
