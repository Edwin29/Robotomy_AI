# 진도와 의도적 정보 제한 재점검

2026-10-18 KST. 사용자 지적에 따라 **표시용 필드 존재**, **UI 공개 권한**, **현재 실제
표시**를 구분해 다시 조사했다. 기존 UI 목록은 수집 허용 목록이 아니다. 공개 여부를
확인하지 못한 항목은 내부 데이터로 보충하지 않는다. 아래 정적 조사를 바탕으로 후속
구현에 `ConsoleDisclosure`를 추가했다. 최초 조사 시점에는 코드·게임 상태를 바꾸지 않았다.

## 후속 사용자 결정과 구현

사용자는 도구 누적 사용 횟수를 플레이 화면의 카운터로 제공하지 않는다고 확인했다.
따라서 **장치가 누적 사용 횟수·시간을 반환하지 않는 것**이 확정 계약이다. 과거 명령창의
대입 코드·직렬화 참조 존재는 이 계약을 바꾸지 않는다. `UseCountText`와 제목 참조는
`ConsoleDisclosure`에서 항상 제외한다. 내부 횟수로 플레이어 기억을 보정하지 않는다.

잠금 검사는 텍스트와 게이지가 공통으로 사용하는 `ConsoleUI.Visible`에 통합했다.
도구 기본정보 `Open`, 기록행 `disabled`, E.G.O. 슬롯 `BlockControl`, 일반 관찰 잠금,
직원 `BlackHide`를 확인한다. 필수 덮개 참조가 없어 판단할 수 없으면 제공하지 않는다.
해금 조건 문구는 덮개 안에서 실제 보이는 경우에만 허용한다. 명령창 직원 현재 HP/SP는
진도별 실제 화면 검증 전까지 제외한다. 능력치 최대값을 현재 HP/SP로 해석하지 않는다.

명령창·미션·화면 로그/통신·일반 툴팁·탄환 수의 확인된 표시 참조만 후보로 추가했다.
후보가 됐다는 이유로 바로 전달하지 않으며 기존 가림·잘림·후처리 검사를 모두 적용한다.
런타임 결과와 남은 범위는 [구현 검증 기록](disclosure-implementation.md)을 참고한다.

## HP/SP: 연구 보상을 적용할 수 있는가

**가능하다. 그러나 날짜에 따른 임의 해금표가 아니라 게임이 실제 표시하는 결과를 따라야 한다.**

- `AgentUI.ValidateUIActiate`266772–266797은 `show_agent_ui` 연구 또는 튜토리얼
  단계 조건으로 직원 인디케이터 표시를 허용한다. 튜토리얼 관측을 본편 초반 공개 상태로
  일반화하면 안 된다.
- `SetActive`266799–266802는 HP/SP 막대를 없애는 대신 형제 `BlackHide` 덮개로
  가린다. 내부 fillAmount는 가린 동안에도 계속 갱신될 수 있다(266843–266880).
- 현재 `ConsoleUI.Visible`은 해당 `BlackHide`가 활성인 경우 제외한다. 월드 HUD도
  별도 검증 전에는 제외하며, 게이지 계약은 내부 정확한 HP 대신 화면의 채워진 픽셀이다.
  이 보호는 유지해야 한다. 연구 전후 런타임 검증까지 완료했다는 뜻은 아니다.
- `ResearchDataModel`206622–206739는 완료 미션·선행 연구·실제 연구 레벨을 통해
  능력을 갱신한다. 단순히 특정 날짜를 넘겼다는 이유로 공개하면 안 된다.

다음 세 값은 별개다.

| 표시 | 판정 |
|---|---|
| 직원 머리 위 현재 HP/SP 바 | 위 연구/튜토리얼 조건과 덮개·현재 렌더 상태 확인 필요 |
| 열린 직원 정보창의 체력/정신력 능력치 | `WorkerPrimaryStatUI.SetStat`271809–271831은 최대치·보너스를 표시. 현재 체력으로 해석하면 안 됨 |
| 명령창 직원 목록의 현재/최대 숫자 | AgentSlot253851–253867에는 숫자 대입이 있으나 상위 가림·prefab 공개 조건 미확인. 초반 공개로 단정하지 않으며 현재 수집 루트에도 없음 |

피해 숫자도 별도 `damage_text` 연구/튜토리얼 조건이 있다(UnitModel211860–211865).

모든 개체의 체력과 피해값을 공개할 수는 없다.

## 도구형 환상체: 해금 조건과 누적 사용 기록

정보창 경로에서는 사용자가 지적한 구분이 확인된다.

- `CreatureInfoKitStatRoot.Initialize`291890–291928은 실제 이름·위험등급·초상화를
  먼저 채우고 사용 조건을 충족하지 못하면 `Open` 덮개를 표시한다. 덮개에는 **필요한
  사용 횟수/시간**이 들어간다. 플레이어의 실제 누적값을 표시하는 코드가 아니다.
- `CreatureInfoKitLayoutController.SetDataList`291766–291790도 실제 기록/사용법을
  먼저 채운 뒤 미해금 행에 `disabled` 덮개와 `needCostText`를 표시한다. 그 숫자는
  현재 누적 횟수가 아니라 **해금 임계조건**이다.
- 격리실의 `SetKitObserveLevel`298463–298479는 관찰 단계를 색/테두리로 표시한다.
  관찰 단계가 보인다고 정확한 누적 사용 횟수가 공개되는 것은 아니다.
- 누적값은 게임에 저장된다(194791–194802). 이를 곧바로 이번 플레이어가 관찰한
  횟수로 취급하면 재시도·이전 날짜·이전 기록도 섞일 수 있다.

다음은 최초 조사 때 확인한 코드 흔적이다. **플레이어 공개 허용 근거로 사용하지 않는다.**
`KitCreatureRegion.SetData`254298–254315는 `UseCountText`에 누적 횟수/시간을 넣고,
`CommandWindow.CreateWindow`255192–255201에서 호출한다. 단순 미사용 코드라고
단정할 수 없다. 본편 level2의 CommandWindow 컴포넌트 pathID39299를 공개 직렬화 필드
순서에 맞춰 부분 해석하니 `UseCountTitleText`34855와 `UseCountText`33620에 연결됐고,
해당 Text와 조상 GameObject들의 저장 기본값은 활성이다.

이 조사는 **대입·연결·저장 기본값**만 입증한다. 현재 렌더·가림·잘림·실행 중 상태는
입증하지 않는다. 후속 사용자 결정에 따라 누적값은 표시 후보에서 영구 제외했다.
근거와 해석 한계는 Git 제외 `.robotomy/analysis/progression/kit-command-prefab.json`에 남겼다.

플레이어가 직접 센 횟수는 **자신의 관찰에 근거한 기억/추정**으로 남길 수 있다.
관찰한 사용 시작/완료와 기억의 범위를 명시하고, 장치가 내부 누적 카운터로 정답을
맞춰주거나 놓친 사용을 몰래 보충하지 않는다. 임계조건 공개로 추론하는 것 역시 플레이어 판단이다.

## 수정 전 수집기의 보호와 확인한 공백

- 직원 BlackHide, 일반 CreatureInfoOpenArea 잠금, 앞쪽 Graphic, 화면 밖·잘림,
  미검증 카메라 후처리 차단은 이미 있다.
- 그러나 `ConsoleUI.Locked`138–151에는 **CreatureInfoKitStatRoot.Open /
  CreatureInfoKitOpenArea / KitDataSlot.disabled / EquipSlot.BlockControl** 전용 검사가 없다.
  이들은 일반 잠금 클래스와 다르며 tool/EGO 자식 UI는 당시 정보창 수집 후보에 들어갔다.
- 일반 가림 검사로 차단될 수는 있으나 전용 덮개의 모든 경우를 검증한 것은 아니다.
  이는 **정적으로 확인한 보호 범위의 공백**이며 실제 숨은 내용 누출을 재현했다는 뜻은 아니다.
- 후속 구현은 이 명시적 잠금 공백을 보완한다. 실제 진행에 따른 모든 변형의 검증까지
  완료했다는 뜻은 아니다. 보호를 통과하지 못한 경우 PNG 관람 또는 미관측으로 남긴다.

## 앞으로 적용할 정보 계약과 검증

1. 공개 권한은 게임의 연구·관찰·보상·개체 예외를 따르되 응답 내용은 현재 최종 표시에서
   가져온다. 해금 플래그나 내부 ID 자체를 플레이어에게 덤프하지 않는다.
2. 가린 값은 null/미관측으로 취급하고0으로 바꾸지 않는다. 물음표·계산 불가·범위·단계·
   막대 등 화면의 정보량을 유지한다. 숨겨진 실제 값으로 교정하지 않는다.
3. 동일 프레임의 공개·가림 결과와 텍스트/막대/화면을 묶는다. 오래된 공개 값을 최신처럼
   유지하지 않는다. 과거 기록에는 당시 시각을 유지한다.
4. 테스트는 `미해금 → 해금 → 창 닫힘/탭·스크롤 변경 → 가림/특수 표시 제한`을 비교한다.
   같은 내부 수치가 계속 갱신되어도 미해금·가림에서는 출력되지 않아야 한다.
5. 도구 해금 전/후, EGO 요구 단계 전/후, HP 연구 전/후, 피해 숫자 연구 전/후,
   카운터 Unknown/None/숫자, 계산 불가/정성 등급, 잠긴 탄환과 특수전 변조를 각각 검증한다.

요약하면 진도 반영은 구현 가능하지만 **현재 모든 항목에서 보장된 것은 아니다.**
기존의 누락 목록은 공개 조건과 의도된 은폐를 확인하는 체크리스트로 수정하며,
장치가 인간이 볼 수 없는 정보를 편의상 보충하는 방향으로 구현하지 않는다.
