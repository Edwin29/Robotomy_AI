# AI 우선 입출력 어댑터 검토

2026-10-23. 현재 Python 소스의 정적 검토와 사용자 요구를 바탕으로 한 설계안이다.
이 문서 작성으로 게임 기능이나 MCP 계약을 변경하지 않았다. 게임 조작·재시작·세이브 변경은 하지 않았다.
아래 제안의 비용 절감률과 플레이 속도는 아직 측정하지 않았다.

## 기준

AI용 게임기는 AI의 사용 편의를 우선한다. 좌표 계산, ID 변환, 상태 재조립,
중복 제거, 시간 정렬처럼 의미 판단이 필요 없는 일은 게임기가 맡는다.
사용자는 판단, 관심, 감상, 기억 형성의 주체를 플레이어로 남겨 두기를 원한다.
따라서 편의 기능은 정보의 표현과 조작을 개선하며, 숨은 정답이나 자동 전략을 제공하지 않는다.

최적화 단위는 JSON 바이트 수만이 아니다. 한 행동에 필요한 모델 왕복 횟수,
서로 다른 응답을 연결하는 부담, 입력 실패 후 복구 횟수까지 포함한다.
짧아도 모델이 여러 이전 응답을 복원해야 하는 형식보다 조금 길어도 바로 사용할 수 있는 형식이 낫다.

## 이미 갖춰진 기반

- `robotomy/facility.py`: 고정 시설 ID, 관찰한 지도와 현재 가시 시설의 분리, 연결·상대 위치.
- `robotomy/quick_input.py`: 대상 지정 L/R/H, 직원 이동, 작업 배정을 포함한 짧은 intent 묶음.
- `robotomy/live.py:deliver`, `robotomy/perception.py:Delivery`: 관찰과 입력 결과가 같은 diff 기준을 공유.
- `quick_input.py:offered`: 입력 뒤 관찰과 소리 반환. `mcp_server.py:game_input`은 선택적으로 이미지도 반환.
- `live.py:deliver`: 입력 후 관찰에도 공통 이벤트 전달 경로를 사용한다.
- `perception.py:compact_audio`: 연속된 같은 소리의 묶음 전달.

따라서 위 기능을 다시 만들기보다, 기존 경로의 일관성과 모델용 표현을 개선하는 편이 적절하다.

## 권장하는 모델용 응답

아래는 개념 예시이며 현재 호출 문법이 아니다. 직원 이름과 값도 예시다.

```json
{
  "view": "v42",
  "screen": "operation",
  "playback": {"paused": true, "speed": 2},
  "events": [],
  "action": {
    "id": "a18",
    "dispatch": "sent",
    "observed": "employee_selected",
    "subject": "staff:7"
  },
  "updated": {
    "employees": [
      {"ref": "staff:7", "name": "브룩", "selected": true,
       "location": {"facility": "corridor:12", "relative_x": 0.62},
       "hp_bar": {"fraction": 0.58}, "state": "이동 중"}
    ]
  },
  "left_view": [],
  "audio": []
}
```

- `staff:7` 같은 짧은 ref는 예시다. 실제로는 기존 안정 ID를 유지하면서 짧은 별칭을 붙일지 결정한다.
  다시 로드된 게임/세션에서 다른 직원을 이전 ref로 잘못 조작하지 않도록 범위를 명확히 한다.
- 모델이 ref만 복사해 다음 입력에 사용할 수 있어야 한다. 이름은 사람이 이해하기 위한 표시이며 고유 키를 대신하지 않는다.
- 위 예시의 HP는 공개 막대 잔량이다. 막대만 보일 때 정확한 내부 HP로 바꾸지 않는다.
- 갱신 행에는 이름과 현재 핵심 상태를 함께 제공한다. 긴 장비 설명·고정 지도·기존 대사는 반복하지 않는다.
- 바뀌지 않은 값, 더 이상 보이지 않는 값, 미해금 값, 읽기 실패를 모두 빈 값 하나로 취급하지 않는다.
  흔한 정상 응답에는 진단 문구를 반복하지 않고 필요한 상태만 표시한다.
- 전체 상태 복원은 어댑터가 담당한다. 재연결·컨텍스트 압축 뒤에는 현재 공개 상태를 한 번에 재조회할 수 있어야 한다.
  과거에 관찰한 화면 밖 위치는 현재 위치처럼 반환하지 않는다.
- 주요 사건은 일반 행보다 먼저 반환하고, 작은 수치 흔들림은 묶는다. 새 출현·사망·보호막 소멸 등은 수치 양자화로 지우지 않는다.
- 표시 반올림/묶음은 원시 관측과 구분한다. 정밀 수치가 필요한 호출에서는 실제 공개 정밀도로 조회할 수 있게 한다.

## 입력을 더 편하게 만드는 방향

지금의 `["L", 대상]` 형태는 유지할 가치가 있다. 복잡한 자연어 파서나 새로운 축약 언어를 추가할 필요는 없다.
짧은 클릭, 이름 있는 이동/작업 명령, 짧은 순서 실행이 **같은 대상 참조**를 쓰도록 맞추는 것이 우선이다.

좌표가 필요한 경우도 화면 픽셀, 시설 내부 상대 위치, 고정 시설 ID를 명확히 구분한다.
예를 들어 시설 안의 특정 지점으로 이동하고 싶다면 시설 ID와 정규화된 내부 위치를 주고,
카메라·줌·창 크기에 따른 실제 클릭 위치는 실행 직전에 게임기가 계산한다.
이때 실제로 클릭할 수 있는 현재 화면 지점인지 확인하며, 모델의 목표 위치를 게임 내부에 강제로 덮어쓰지 않는다.

상태 지정 입력에는 요청 ID를 사용해 재전송을 구분하는 방안이 유용하다.
이미 입력했는지 불명확한 명령을 자동 재실행하지 않는다. 명백한 입력 전 참조 갱신은 게임기 내부에서 처리할 수 있다.
이를 위해 플레이어에게 매번 view ID와 준비된 decision ID를 조합하도록 요구할 필요는 없다.

결과는 행동에 맞게 제공한다. 직원 선택에는 선택된 이름, 배속 변경에는 실제 표시 배속,
작업 배정에는 해당 행과 이후 관찰된 상태가 유용하다. 전체 내부 receipt를 반복하는 대신 trace 참조를 두고,
디버깅 원장은 보존한다. 작업 명령 전송을 작업 시작이나 완료로 표기하지 않는다.

## 시간·전투·이미지 결합

모션, 피해 표시, 보호막, 투사체, 소리에는 공통 관측 시간과 엔티티 ref를 사용한다.
게임 시간과 실제 시간, 배속·일시정지 상태는 구분한다. 서로 다른 프레임에서 얻은 정보를 같은 순간이라고 꾸미지 않는다.

피해 표시처럼 순간적인 정보는 상태 diff에 끼워 넣기보다 이벤트로 보존하고,
한 대상의 짧은 구간으로 묶되 타격 횟수·표시값·타이밍을 다시 확인할 수 있게 한다.
모션과 타격이 함께 보인 사실과 공격 원인이라는 추정은 구분한다.
공격 관계를 모르는 상태에서도 시간·위치가 맞는 단서 묶음을 제공할 수 있다.
이 방식은 숨은 공격 타이머나 사거리 정보를 요구하지 않는다.

이미지는 구조화 상태와 같은 관측 기준으로 연결하고, 대상 크롭/전후 프레임을 직접 요청할 수 있게 한다.
스토리 원문과 표정·새 연출은 짧은 전투 요약 형식으로 강제 축약하지 않는다.
전투·작업창·이야기의 표현은 달라도 동일한 ref, 시간, 사건 커서, 입력 결과 계약을 공유한다.

현재 `Delivery`는 해상도도 전체 기준 초기화 조건에 포함한다.
장기적으로 세계 상태와 화면 투영 버전을 나누면 창 크기 변화마다 고정 지도를 재전송하는 일을 줄일 수 있다.
단, 화면 픽셀과 클릭 좌표는 반드시 새 투영 기준으로 무효화/갱신해야 한다.

## 단계와 평가

1. 동일 ref의 관찰→입력 연결, 오류 후보 반환, 입력 결과 형식을 먼저 통일한다.
2. 기계용 원장/diff 위에 모델용 현재 행 요약을 추가한다. 기존 원본과 기록 ID는 보존한다.
3. 상태 지정 입력, 대상 기반 이미지, 같은 문법의 짧은 예약을 추가한다.
4. 모션·피해·효과의 시간 관계를 독립 이벤트 채널로 연결한다.

검증은 같은 기록을 재생한 형식 비교부터 시작한다. 대상 식별, 선택 확인, 저체력 직원 찾기,
현재 작업창에서 배정, 피해/효과 변화 이해에 필요한 호출 수와 응답 크기를 비교한다.
실제 모델 토큰 수와 판단 시간은 별도로 측정하며 JSON 크기만으로 추론 속도 개선을 단정하지 않는다.
정확성은 누락 사건, 동명이인 오선택, 화면 밖 정보 유출, 오래된 좌표 재사용,
중복 입력 여부를 중심으로 확인한다. 실시간 게임 검증은 분리된 검증용 게임에서 수행한다.

목표는 새 프레임워크의 전면 교체가 아니다. 이미 잘 작동하는 고정 지도와 간단 입력을 유지하면서,
모델이 반복해서 수행하던 자료 정리와 연결 작업을 어댑터로 옮기는 것이다.
