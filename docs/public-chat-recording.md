# 공개 채팅 발언 수집

플레이어가 채팅에 실제로 출력한 판단·감상·오해·정정의 원문을 별도 프로세스가 수집한다.
게임/LLM/MCP 입력 호출 경로에 수집·파일쓰기·추가 모델 호출을 넣지 않는다. 기록 때문에
게임을 일시정지하거나 매번 메모 도구를 호출할 필요가 없다. 내부 추론 기록은 수집하지 않는다.

## 범위와 원본

- `.robotomy/experience/chat-sources.json`에 운영자가 명시한 Codex 채팅만 읽는다.
  현재 등록은 `튜토리얼 한 구간 플레이`, thread `01a14d60-88fa-7dd1-9d7b-84927a35a157`이다.
  다른 채팅/새 에이전트의 새 채팅은 자동 수집하지 않으며 별도 등록해야 한다.
- Codex 로컬 rollout을 읽기 전용으로 열고 session ID와 실제 작업 폴더를 검증한다.
- 완료된 assistant message의 commentary/final/final_answer 및 output_text만 통과시킨다.
  reasoning/analysis, 도구 응답, 개발자 메시지, 사용자 첨부, 중복 완료 이벤트를 저장하지 않는다.
- `text_parts`는 원문 부분 배열, `text`는 그대로 이어붙인 문자열이다. 번역·요약·오타 수정 없음.
  Markdown 표시용 들여쓰기와 별개로 JSONL에 원문을 보존한다.
- `source_at`은 Codex 로그의 발언 기록 시각이며 화면 픽셀이 표시된 정확한 시각이나 게임 시간이 아니다.
  `imported_at`은 수집 시각이다. 기존 자료는 `backfill`, 이후 추가분은 `live_tail`로 구분한다.
- ID는 thread/message/text의 해시로 결정해 재실행·커서 저장 실패 때 중복을 방지한다.
  다른 정정 발언은 새 사건으로 남고 앞선 오해를 삭제하지 않는다.

## 기존 경험과 연결

원장에 `public_chat_message`를 추가하며 기존 seq/data는 변경하지 않는다. 각 발언에는
시도 ID, 채팅/메시지/턴 ID, 원문 시각, 수집 방식 및 기존 사건의 앞뒤 ID가 붙는다.
앞뒤 ID는 시간상 이웃이지 해당 발언의 근거나 인과관계를 입증하는 필드가 아니다.
같은 시도에 속하는지는 명시적 turn binding 또는 시각 구간/한 턴의 유일한 시도로 연결한다.
애매하면 추측하지 않고 pending으로 보존한다. 1000개를 넘으면 오류로 알리고 원본 커서를
진행시키지 않는다. 실제 수집 원본은 지우거나 수정하지 않는다.

`Days/Day-XX-Attempt-XX.chat.md`와 `Logs/*.chat.jsonl`은 공개 발언 시각순이다.
`Logs/*.timeline.jsonl`은 기존 관찰/입력/회고와 발언을 원래 시각순으로 합친 자료다.
기존 `Logs/*.jsonl` 및 MCP 사건 페이지의 seq는 원장 추가 순서여서 사후 보충분은 뒤에 붙는다.
별도 채팅 파일은 플레이 중에도 갱신된다. 일반 회고 문서/전체 사건 출력은 기존 종료·회고·내보내기 시 갱신한다.
수집기가 종료 후 마지막 발언을 받으면 통합 시간순 파일도 갱신한다.

내보내기는 그 시점의 스냅샷이다. `export_player_experience`를 호출한 뒤 출력한 마지막 채팅까지
그 앞서 만든 묶음에 자동으로 들어가지는 않는다. 최종 발언 수집 이후 다시 내보내면 포함된다.
옛 묶음은 수정하지 않는다. 감상과 잘못된 발언을 확정된 게임 지식으로 자동 승격하지 않는다.

## 실행·복구·성능

- `scripts/run_player_mcp.py`가 시작될 때 `scripts/watch_player_chat.py`를 숨김 실행한다.
  이름 있는 Windows mutex로 같은 프로젝트의 수집기를 하나만 유지한다.
- 1초 간격으로 마지막 읽기 위치 이후만 읽는다. 한 번 최대 약 8MiB이며 JSONL 한 줄은
  완결된 단위로 읽는다. 대형 단일 줄은 한도를 넘을 수 있다. 미완성 줄은 다음에 재시도한다.
- 별도 프로세스의 짧은 SQLite 트랜잭션을 사용한다. 저장이 막히면 다음 주기에 재시도하며,
  commit 이전에 커서를 전진시키지 않는다. 게임 입력에서 이 완료를 기다리지 않는다.
- `chat-status.json`의 ready/error, at, poll_ms, pending_unassociated를 운영자가 확인한다.
  오래된 heartbeat는 실행 중이라는 증거가 아니다. 오류를 정상 수집으로 숨기지 않는다.
- Codex가 닫혀 수집기도 종료돼도 다음 MCP 시작 때 디스크 로그의 미수집분을 따라잡는다.
  Codex가 로컬 로그를 쓰기 전 중단되거나 원본을 삭제한 경우까지 무손실을 보장하지 않는다.
- 저장 계층 변경이므로 이미 연결된 구형 MCP는 한 번 재연결해야 한다. 현재 수집기는 별도로 가동했다.

- 기존 내보내기를 보존하고 채팅/통합 로그를 포함한 새 묶음을 생성했다. 파일115개 해시 검증 통과.
