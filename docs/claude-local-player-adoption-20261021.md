# 로컬 플레이어 도입 방법 — Claude 의견 (2026-10-21)

작성: Claude (조언 역할). 전제: 사용자가 로컬 플레이어로 전환하기로 정했다. 이유는 본편만 사람 기준 100시간 이상이고,
기록·회고까지 하면 가동 시간이 더 늘어나 구독형 플레이어로는 감당할 수 없다는 것이다.
이 문서는 "할지 말지"가 아니라 "어떻게 들일지"를 다룬다. 수치 중 측정값은 출처를 적고, 나머지는 추정이라고 표시한다.
앞 문서 [로컬 플레이어 도입 검토](claude-local-player-review-20261021.md)의 측정값을 그대로 쓴다.

## 핵심 판단

현재 구조는 "큰 모델이 큰 문맥을 계속 들고 실시간으로 따라가는" 방식이다(호출당 문맥 중앙값 약 20만 토큰, 호출 간격 중앙값 16초).
로컬 모델로 이 방식을 흉내 내면 실패한다. 대신 세 가지를 바꾼다.

1. **속도 문제를 일시정지로 바꾼다.** 이 게임은 정지 상태에서 지시를 내릴 수 있다. 로컬 플레이어는 "정지 → 생각 → 지시 → 짧게 재생 → 사건이나 시간으로 다시 정지"로 진행한다. 그러면 필요한 것은 반응 속도가 아니라 총 처리량이 되고, 느린 모델도 플레이할 수 있다. 게임이 정지를 막는 구간은 우회하지 않고 별도 조건으로 기록한다.
2. **문맥을 8천~1만6천 토큰 안에 넣는다.** 큰 기억은 디스크에 두고, 매 판단에는 고정된 짧은 틀만 넣는다(아래 3절).
3. **Codex 대신 직접 만든 얇은 실행기를 호스트로 쓴다.** 로컬 추론 서버(LM Studio 또는 llama.cpp의 OpenAI 호환 서버)를 부르고, 기존 `robotomy` 도구를 같은 프로세스에서 호출한다. 실행기가 대화 원문을 직접 가지므로 공개 발언 기록, 압축 전 정지, 사용자 개입 기록을 Codex 기록 파싱 없이 처리할 수 있다.

판단은 처음부터 끝까지 **로컬 모델 하나**가 한다. 게임기는 지금처럼 관찰·입력·기록·조건 대기만 맡는다.

## 1. 이 PC의 자원 제약

| 자원 | 상황 | 영향 |
|---|---|---|
| VRAM 8GB | 게임 실행 중 사용 약 3.4GB, 여유 약 4.5GB (10-21 순간값, 전투 최대치 아님) | 게임과 동시에 GPU에 다 올릴 수 있는 것은 4B급 Q4 + 짧은 문맥 정도(추정) |
| CPU 6코어 | 사용자가 게임 CPU 병목을 우려 | 모델 일부를 CPU로 넘기면 게임과 직접 경쟁. 정지 중 추론이면 경쟁이 덜함(추정) |
| RAM 32GB | 조회 시 여유 약 12GB | MoE 모델의 전문가 가중치를 RAM에 두는 방식은 가능성 있음 |

정지 상태에서 추론한다는 점이 여기서도 중요하다. 정지 중에는 게임의 CPU·GPU 부하가 줄어들 가능성이 크다(미측정). 이 값을 먼저 측정해야 모델 크기를 정할 수 있다.

## 2. 모델 후보를 고르는 방식

모델 이름으로 먼저 정하지 않는다. 이 PC에서 아래 순서로 거른다.

| 단계 | 기준 |
|---|---|
| 적재 | 게임을 실행하고 정지한 상태에서 8k/16k 문맥이 메모리 부족 없이 올라가는가. KV 캐시 양자화 포함 |
| 속도 | 판단 1회(입력 8k, 출력 300토큰 정도)가 정지 중 30초 안에 끝나는가. 처리량 기준이라 실시간 기준보다 느슨하게 둔다 |
| 도구 형식 | 정해진 JSON 형식의 행동을 몇 %나 올바르게 내는가 |
| 판단 품질 | 4절의 재생 시험 |
| 시각 | 스토리·새 환상체 외형을 직접 볼 수 있는가 |

설치된 후보 중에서는 다음이 출발점이다.

- `google/gemma-4-e2b` (4.41GB 파일, 이미지 지원 표시): 게임과 함께 GPU에 올라갈 가능성이 가장 높다. 품질이 가장 걱정된다.
- `qwen/qwen3-vl-8b` (6.19GB): 시각과 품질에서 유리하지만, 게임과 함께면 일부를 CPU로 넘겨야 한다.
- `openai/gpt-oss-20b` (12.11GB, MoE): 이미지를 못 본다. 전문가 가중치를 RAM에 두면 돌릴 수는 있겠지만 CPU를 쓴다.

**시각과 단일 판단 모델의 충돌:** 판단 모델이 이미지를 못 보면 스토리·외형 관람을 다른 모델이 대신하게 되고, 감상의 주체가 바뀐다. 그래서 판단 모델은 이미지 입력이 되는 모델이어야 한다. 단, 이미지는 정지 상태에서 필요한 장면에만 보낸다(앞 조언의 영역 잘라 보내기).

설치되지 않은 Qwen3.5-4B나 다른 4B급 비전 모델도 같은 기준으로 비교 대상에 넣을 수 있다. 성능은 확인하지 않았다.

## 3. 문맥 설계 (8k~16k)

매 판단에 들어가는 내용을 고정된 칸으로 나눈다. 토큰 수는 목표치다.

| 칸 | 내용 | 목표 |
|---|---|---|
| 고정 지침 | 페르소나 요약, 행동 형식, 핵심 규칙 | 1.5k |
| 도구 | 플레이용 8~10개만. 현재 MCP의 약 50개 도구를 그대로 노출하지 않는다 | 1k |
| 현재 상태표 | 게임기가 만든 직원·환상체·경보 요약. 매번 새로 생성 | 2k |
| 미완료 목록 | 내가 내린 지시, 진행 중 작업, 예약된 정지·대기 | 0.5k |
| 최근 사건 | 직전 정지 이후의 시간순 사건 | 1k |
| 꺼내 온 기억 | 이번 판단에 관련된 플레이북·환상체 메모·직원 평가, 출처 포함 | 1.5k |
| 직전 몇 차례의 내 판단 | 대화 전체가 아니라 최근 3~5회 | 1k |

- 대화를 계속 이어 붙이지 않는다. 매 판단마다 위 틀을 새로 채운다. 이렇게 하면 100시간을 돌아도 문맥이 늘지 않고 압축도 없다.
- 기억 검색은 모델이 질의어를 고르고, 검색기는 출처와 함께 결과만 돌려준다. 무엇을 꺼낼지 검색기가 판정하면 판단이 섞인다.
- 일차 종료 회고는 게임을 닫거나 정지한 뒤 **같은 모델**로 문맥을 길게 잡아 따로 돌린다. 이때는 VRAM을 게임과 나누지 않아도 된다.
- `config/player/AGENTS.md`(49KB)는 이 틀에 들어가지 않는다. 로컬 플레이어용 짧은 지침을 새로 쓰고, 나머지는 필요할 때 꺼내는 참고 자료로 바꾼다.

## 4. 품질을 확인하는 방법: 기존 기록 재생

10-18~21 Sol 플레이어 기록(`~/.codex/sessions/2026/10/18/rollout-…`)에는 실제 관찰 결과와 Sol이 한 행동이 약 3,300회 들어 있다.
이것을 로컬 후보 시험 자료로 쓴다.

1. 각 시점의 관찰을 3절 틀로 줄여 로컬 모델에 주고 행동을 받는다. 게임은 조작하지 않는다.
2. 형식 오류율, 존재하지 않는 대상 지정, 보이지 않는 정보 사용 같은 명백한 오류를 센다.
3. Sol과의 일치율은 참고만 한다. Sol의 행동이 정답은 아니다. 위기 장면(사망·시련·탈출)은 사람이 몇십 개 골라 질적으로 본다.

이 시험은 게임을 켜지 않고 할 수 있다. 문맥 틀이 상태를 제대로 전달하는지도 함께 드러난다.

## 5. 경험 이전과 정체성

- 로컬 플레이어는 Sol과 다른 플레이어다. 새 모델 ID로 경험을 귀속한다.
- Sol이 남긴 플레이북·회고는 "이전 플레이어의 기록"으로 출처를 붙여 물려준다. 이것은 프로젝트 목표인 "다른 모델로 경험 이전"의 첫 실제 사례가 된다.
- Run 정의는 바뀌지 않는다. 플레이어가 바뀌어도 게임의 1일차 회귀가 없으면 같은 Run이다.

## 6. 도입 순서

| 단계 | 내용 | 게임 조작 |
|---|---|---|
| 0 | 게임 정지 상태와 전투 상태의 VRAM·CPU 측정. 후보별 적재·속도 측정 | 사용자가 띄운 게임을 읽기만 |
| 1 | 3절 문맥 틀과 플레이용 도구 묶음 설계, 로컬 플레이어 지침 작성 | 없음 |
| 2 | 4절 기록 재생 시험으로 후보 1개 선택 | 없음 |
| 3 | 얇은 실행기 구현. 정지 기반 진행, 대화 원문 기록, 사용자 개입 | 없음(합성 시험) |
| 4 | 쉬운 일차를 별도 세이브에서 짧게 플레이. 처리량(게임 1일당 실제 시간), 사망, 사람 개입 기록 | 승인 후 |
| 5 | 본 플레이 전환 | 승인 후 |

구현은 Codex 몫이다. Codex 구독은 이 개발과 가끔 하는 검토에 쓰고, 플레이 판단에는 쓰지 않는다.

## 7. 위험과 대비

- **작은 모델이 어려운 일차를 못 넘길 수 있다.** 게임기가 정답을 주게 하는 식으로 메우지 않는다. 대신 의도 단위 행동, 유효한 대상 목록처럼 "입력 실수"를 줄이는 쪽으로 돕는다. 그래도 막히면 사람 개입으로 기록하고 넘어가는 규칙을 미리 정한다.
- **정지 중심 플레이는 사람과 다르다.** 사람보다 자주 멈춘다. 실험 조건으로 기록한다.
- **하드웨어 한계가 결정적일 수 있다.** 0단계에서 게임과 함께 쓸 수 있는 모델이 2B급뿐이라면, VRAM이 큰 GPU나 모델 전용 두 번째 PC가 가장 확실한 해결책이다. 추가 지출 상한(3만원)으로는 어렵다는 점을 미리 알려 둔다.

## 8. 사용자가 정할 것

1. 정지 중심 진행("정지하고 생각하기")을 기본 플레이 방식으로 받아들일지.
2. 판단 모델이 이미지를 볼 수 있어야 한다는 조건을 유지할지. 유지하면 후보가 좁아진다.
3. 0단계 측정을 위해 게임을 띄운 상태에서 자원 측정을 해도 되는지.
