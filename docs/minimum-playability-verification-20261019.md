## 속도 비교와 해석

같은 종류의 직원 선택 화면에서 `직원 배정 → 2배속` 두 입력을 비교했다. 최초 관찰부터 입력 준비·실행 완료까지 측정했다. 후속 증거용 이미지 대기, LLM 추론·통신 시간은 포함하지 않았다.

| 방식 | 실행 구간 | 중간 포함 관찰 호출 |
| --- | ---: | ---: |
| 수정 전: 각각 관찰·입력 | 875.20ms | 2 |
| 수정 후: 두 입력 예약, 최종 빌드 | 707.01ms | 1 |
| 수정 과정의 같은 경로 재측정 | 748.72ms / 860.71ms | 1 |

소수 표본이며 게임의 프레임 타이밍과 직원 위치가 완전히 같지 않다. **하루 플레이 시간이 몇 % 줄어든다는 측정은 아니다.** 기대하는 주된 이득은 HP/SP 이미지 판독과 배정 후의 중간 모델 왕복을 줄이는 것이다. 기존 화면을 이미 알고 있는 상황에서 더 직접적으로 작업을 이어갈 수 있다.

최종 걷기 관찰은 약 6초 동안 55개 표본이었고, 진단으로 직원 에덴에 대응함을 확인한 트랙은 17개였다. 움직임 계산의 표본별 소요는 중앙값 17.32ms, 최대 48.83ms였다. 카메라 이동 측정은 중앙값 17.19ms, 최대 50.93ms였다. GPU 전환이나 비용이 사실상 없는 관찰을 달성한 것은 아니다.

## 정보 경계와 치명적 품질 검토

- HP/SP는 화면의 허용된 Text에서만 읽는다. 직원 모델의 실제 HP/SP나 숨겨진 막대 값을 대체값으로 넣지 않았다. 기존 진도별 정보 공개 규칙과 도구 사용 횟수 차단도 유지한다.
- 배속은 화면 아이콘·채움색·공개된 버튼 상태를 함께 확인한다. 게임 내부 timeScale을 플레이어 데이터로 사용하지 않는다. Hover 색만으로 선택 상태를 오판하지 않도록 구분한다.
- 벡터는 실제 표시 위치의 변화다. 목적지·경로·내부 이동 스탯은 읽지 않는다. 플레이어에게는 일시적인 익명 트랙만 주고, 직원 내부 이름 매핑은 엔지니어링 진단에만 둔다.
- 화면 밖, 실제 가림, 알려지지 않은 렌더 효과의 기존 차단을 유지한다. 이번 실제 검증 범위에서 가려진 정보가 새로 노출되는 현상은 발견하지 못했다. 모든 보스 효과나 겹침을 검증했다는 뜻은 아니다.
- 소재/애니메이션 바인딩은 `PlaybackDisplay`, `MotionRenderPolicy`, `MotionStencil`에 모았다. 게임에서 조사한 자산 이름·색·설정에 의존하는 코드는 있지만 특정 직원 이름/ID나 화면 좌표로 동작을 고정하지 않았다.
- 새 alpha 캐시는 8MiB·256개 텍스처로 제한하며 장면/화면 조건 변경 시 기존 캐시와 함께 초기화한다. 기존 atlas 캐시도 별도로 존재하므로 전체가 8MiB라는 의미는 아니다.
- 예약은 1~5개 입력, 합계 5초, 전송 기한 10초의 기존 한도를 유지한다. 다음 대상이 같은 의미의 조작 가능한 대상이고 요청 지점에 있어야 계속한다. 취소는 현재의 짧은 입력이 끝난 뒤 다음 입력부터 막는다.

확인한 범위에서 적용을 막을 치명적 정보 유출·무제한 캐시·특정 직원 하드코딩은 발견하지 못했다. 2px 표시 패치의 alpha 검사는 근사치이며 GPU의 최종 픽셀을 완전히 재현하지 않는다. 일부 자세·겹침·확대율에서는 트랙이 끊기고 다시 획득될 수 있다. 이 부분과 모든 환상체 지원은 이번 완료 조건에서 제외한다.
