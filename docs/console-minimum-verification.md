# 최소 게임기 구현과 실제 검증 — 2026-10-17

실제 Unity 2017.4.7f1 복사본에 가상 입력, 세 UI의 표시 정보, 익명 소리 이벤트,
최종 프레임 캡처를 연결했다. 이 구성으로 튜토리얼 1을 사람 조작 없이 완료했다.
모든 보스전의 가림 처리나 초 단위 전투 대응까지 검증한 버전은 아니다.

2026-10-18 후속 변경: [진도별 정보 제한 구현](disclosure-implementation.md)에서 도구 누적값
영구 차단과 잠금 검사를 보강하고 운영 UI5분류를 후보에 추가했다. 아래는 최초 최소 버전의
검증 기록이며 현재 전체 공개 범위나 최신 테스트 개수를 뜻하지 않는다.

## 장치와 플레이어

- 장치: 프레임·표시 문구·재생 이벤트 제공, 요청한 입력 실행, 관찰·판단·결과 기록.
- 플레이어: 화면 해석, 목표 선택, 행동 이유·예상 결과, 후속 화면을 근거로 성공 여부 판단.
- 게임의 작업 완료 함수, 체력, 클리포트 모델, 정보 해금 플래그는 조작하지 않는다.
- 사람이 보는 웹 페이지는 GET 관찰 전용이다. 클릭이 게임으로 전달되지 않으며 POST는 405다.
- 새 모델·유료 API·Computer Use 브리지 없이 동작한다. 플레이어 LLM의 추론 사용량은 별개다.

## 최종 표시 정보의 범위

OCR 대신 실제 UI Text의 생성된 글자 사각형과 표시 상태를 확인한다. 전체 게임 데이터나
전체 씬의 텍스트를 플레이어에게 덤프하지 않는다. 화면 내 세 패널의 허용 문구만
`text/panel/x/y/width/height`로 전달하며 표준 버튼도 이미 허용된 문구를 재사용한다.

다음은 제외한다: 비활성·투명·페이드 중 객체, 화면 밖·부분 잘림, 회전된 글자,
Mask/RectMask2D에 걸린 글자, 위에 겹친 Graphic, 미개방 덮개 아래 내용,
직원 HUD BlackHide, 검증하지 않은 재질과 렌더 효과, 월드 공간 HUD,
AI 포인터에 가려진 문구, 표시되지 않은 뒷부분이 있는 긴 텍스트.
평상시 MainCamera의 두 알려진 필터는 UI 카메라와 분리해 취급하며 해당 월드 HUD는 계속 제외한다.

**실제 대조:** 직원 데봉의 이름·최대 체력32·정신력32·작업 관련35, 에너지
0/20 → 9/20 → 19/20 → 20/20을 화면과 대조했다. 잠긴 환상체 정보 창은
76개 잠금 구역 후보를 제외했다. 뒤의 에너지·직원 정보도 모두 제외했다.
정상 클릭으로 기본 정보를 연 뒤에만 TETH, RED, 1–2, E-Box10이 전달됐다.
이것은 이 장면들의 검증이며 전체 표시 문구의 정확도 백분율 측정은 아니다.

**보수적 누락이 있다.** 긴 도감 본문, 색 태그가 있는 일부 수치, 이미지로 그린 글자,
작업 선택창과 튜토리얼 설명은 캡처로 읽어야 한다. 막대 픽셀 길이 출력 코드는 있지만
실제 시험에서는 장식 이미지/월드 HUD 제한으로 `gauges=[]`였다. HP 막대 지원 완료로 취급하지 않는다.
비표준 IMGUI·스프라이트·임의 셰이더를 포함한 모든 픽셀 가림을 증명한 것은 아니다.
본편 보스전에서 표시 추출을 사용하려면 해당 효과별 검증이 추가로 필요하다.

## 주기와 소리

- UI/소리 상태 게시 목표: 약 100ms, 유효기간 750ms. 오래된 정보는 입력 근거로 거부.
- PNG 목표: 약 1초. 실제 아래 표본에서는 약 0.9Hz. EndOfFrame의 1280×720 최종 이미지다.
- 페이지 표시: 2초 새로고침. 실시간 시청은 네이티브 게임 창에서도 가능하다.
- 두 채널은 별도 시점이다. PNG의 세션·PID·씬·해시를 확인하지만 같은 순간임을 보장하지 않는다.
- 입력은 Unity 프레임에 따라 실행한다. 이것을 LLM의 반응 속도나 종단 지연 보장으로 해석하지 않는다.

소리는 자산 이름 대신 세션 내 익명 sound/source 토큰, 순번, 시각, start/stop/pause/resume/
source_idle/source_destroyed/ongoing_detected 이벤트다. 재생 호출 패치 66개, 패치 실패0을 확인했다.
같은 클립을 다시 재생하면 같은 토큰이지만 의미는 플레이어가 경험으로 연결해야 한다.
무음·볼륨·리스너 상태를 확인하며 PlayOnAwake 등은 샘플링된 ongoing_detected로 구분한다.
믹서 출력 파형이나 사람이 실제 듣는 정도를 측정한 결과는 아니다. 개별 겹친 one-shot의 종료,
네이티브/다른 어셈블리의 모든 소리, 거리·믹서에 따른 실제 청취 가능성은 완전하지 않다.

기본 정보 개방 창 5초: 간격101.960ms/P95 126.667ms, 추출 P95 8.008ms.
표본은 해당 PC·장면·부하에 한정한다. 전체 프레임 FPS나 자극→LLM→입력 지연은 측정하지 않았다.
PNG가 메인 스레드를 약60–75ms 사용하는 점은 남은 큰 병목이다.

초기 구현의 Unity IndexedSet 열거 예외를 인덱스 접근으로 수정했다. 실제 효과 클래스명,
글자 영역과 패널 영역 차이, 화면을 덮던 관찰 배너도 수정했다. 동기 파일 쓰기는 제한된
백그라운드 큐로 옮겼다. 초기 직원 창 표본의 UI 추출 중앙값8.474ms/표본 간격250.726ms에서 개선됐다.

플레이 시험 중 관찰 파일의 일시적 부재로 두 행동 준비가 입력 전에 거부됐다.
새로 관찰한 뒤 모델이 새 결정을 만들었으며 불확실한 입력을 자동 재전송하지 않았다.
해당 세션의 게시 오류 누계는5, 큐 초과는0이었다. 이후 Mono File.Replace 대신
Windows MoveFileEx 교체를 적용하고 읽기에서 일시적 부재를 최대4회 짧게 재확인하도록 보완했다.
최종 게시 수정본은 타이틀 30초 표본284개에서 게시 오류0·큐 초과0을 확인했다.
이미지/메타데이터 게시가 별도여서 일시적인 세대 불일치 거부5건은 남았다. 일치하지 않는 이미지는 전달하지 않는다.
이 마지막 수정은 파일 전송 부분이며, 전체 튜토리얼 시험은 그 직전 빌드에서 수행했다.

검증: Python 테스트54개, MCP 합성 계약 왕복19도구, 실제 관찰 MCP/PNG,
실제 가상 포인터·중복 실행 방지·키 유지·중간 중지 검증 통과.
Unity 안의 합성 UI/소리 진단12개도 통과했다. 합성 진단과 실제 잠금 UI 대조는 다른 근거다.

## 사람 마우스 갇힘

원래 게임의 `DeployUI.Start()`에 `Cursor.lockState = Confined` 호출이 있었다.
가상 Input만 분리해도 이 별도 커서 설정은 남을 수 있었다. 복사본에서 Cursor의 잠금·숨김·모양
요청18곳도 가상화하고 시작 시 실제 커서를 None/visible로 복원했다. 포인터 위치는 바꾸지 않는다.

최종 파일 게시 수정본의 Tutorial_2 배치 화면에서도 활성 상태30/30개 표본이
전체 데스크톱 `[0,0,2194,1234]`였고 실제 잠금은 None이었다.
근거는 `.robotomy/live/verification/cursor-deploy-final.json`이다.
웹 observer는 입력·포인터 잠금 기능이 없다. 실험 중 포커스 변경은 이 개발 진단에서만 사용했으며
플레이 시험의 행동에는 Windows 입력/포커스 조작을 사용하지 않았다.
