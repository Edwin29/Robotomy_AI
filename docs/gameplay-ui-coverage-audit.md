# 관리·자원·장비 UI 전달 범위 추가 점검

2026-10-18 KST. [이벤트·스토리 점검](event-story-coverage-audit.md)의 후속이다.
이번에도 코드·DLL·게임 입력을 변경하지 않고 게임 표시 코드와 수집기를 대조했다.
핵심 결론은 **세 정보 패널의 Text 일부를 읽는 기능을 게임 전체의 정보 전달로 볼 수 없다**는 것이다.
정보를 표시하는 게임 UI는 이미 많지만, 수집 루트·이미지 상태·의미 연결이 빠져 있다.

**후속 정정:** [진도·정보 제한 재점검](progression-information-boundary-audit.md)이 공개
판정의 최신 기준이다. 아래 필드·대입 경로는 수집 허용을 의미하지 않는다. HP/SP에는 연구
보상이 있고, 도구 정보의 사용 조건은 누적 사용값과 다르다. 명령창 누적 카운터는 실제
화면 검증 전까지 공개 정보로 취급하지 않는다. 도구·EGO 전용 잠금 보호도 검증이 필요하다.

## 근거와 판정 기준

게임 원본 `Assembly-CSharp.dll` SHA256은
`fb31a592f29a6d8a08e3884cf21d94bc8bd167c9aeefc2eef81a774c70b294bd`,
역분석 파일 `.robotomy/analysis/Assembly-CSharp.decompiled.cs` SHA256은
`3f5b8d807af9b2f416a0499455014ac601f62dcc121ca07cec88d20b39f828af`로 재확인했다.
아래 게임 행 번호는 이 역분석 파일 기준이다. 원문 게임 코드·자산은 Git 제외다.

현재 수집 계약:

- `mods/RobotomyObserver/ConsoleUI.cs:212–224`: EnergyController.ActiveControl,
  AgentInfoWindow, CreatureInfoWindow의 자식 Text/Button만 등록한다.
- 같은 파일의 가시성·잠금·잘림·rich-text 검사에 통과한 문구만 전달한다.
  8자리 색상 태그·긴 문구 등은 표시되어 있어도 제외될 수 있다.
- 게이지는 에너지와 직원 HP/SP만 호출하며 실제로 모두 전달된다는 뜻은 아니다.

  `현재 카운터`, `최대 카운터`, `PE 잔액` 같은 의미 필드로 묶이지 않는다.

**확인**은 실제 응답 근거가 있는 경우, **조건부**는 기존 루트 아래 실제로 배치되고

다른 정보창·인벤토리·후반 UI를 실제로 열어 대조하는 시험은 이번에 수행하지 않았다.

## 정확도와 플레이어 정보 경계

- **작업 성공률:** UICommonTextConverter290657–290668은 내부 확률을 5단계 문구로
  바꾼다. 정보창291475–291487과 배정창 모두 이를 사용한다. 실제 화면의 높음/낮음 등
  문구나 계산 불가 표시를 전달해야 하며 정확한 내부 확률로 바꾸면 안 된다.
- **LOB:** 에너지 패널 LobPoint292816–292832는 플레이 시간에 따른 예상 보상이다.
  DeployUI.pointCount의 현재 보유 LOB와 혼동하면 안 된다.
- **생존 사무직:** 부서 화면이 단계 이미지로 표시하면 그 단계만 전달한다. 반면 실제
  열린 토끼팀 UI가 숫자 집계를 보여주면 그 숫자는 정당한 관측이다. 시설 카메라 밖이라는
  이유로 전역 UI가 공개한 집계까지 없애거나, 반대로 내부 전체 명단을 제공하지 않는다.
- **툴팁:** OverlayManager는 설정/연출에 따라 표시하지 않는 경로가 있다. 저장된 설명
  문자열을 직접 읽지 말고 실제 마우스오버 후 표시된 OverlayText만 읽는다.
- **버튼:** 현재 수집기는 활성·상호작용 가능한 라벨 버튼만 내보내므로 비활성 버튼과
  선택된 배속·탄환·잠긴 슬롯의 의미가 사라진다. 클릭 가능 여부와 표시 상태는 별도다.
- **시각적 부호:** 칸 수·색·아이콘·강조·패널 활성 여부도 정보다. Text 확대만으로
  폭주/탄환/장비 잠금/작업 결과 전달이 완성되지 않는다.

## 후속 구현 단위 제안

1. **실시간 관리:** 방 HUD의 현재 카운터·폭주 제한시간·작업 PE/NE/결과/쿨다운,
   상단 폭주 칸·시련 단서·비상·탄환·일시정지/배속 표시를 먼저 연결한다.
2. **판단과 실행의 연결:** 실제 열린 작업/진압 명령창, 직원 상태, 공통 툴팁을 연결한다.
   입력 성공 receipt와 게임의 명령 수락/취소/불가 표시를 구분한다.
3. **기존 패널 검증:** 환상체별 PE 잔액·최대 카운터·장착 EGO·제작 탭·gift·채용 비용은
   기존 루트를 재사용할 수 있는지 실제 탭/hover/계층/가림을 먼저 확인한다.
4. **여유 있는 장면:** 인벤토리·배치·연구·환상체 선택·일과 결과·매뉴얼은 우선 화면
   캡처와 필요 시 열린 UI 텍스트로 처리한다. 모든 장면을 높은 주기로 숫자화할 필요는 없다.
5. **스토리:** 사용자와 합의한 화면 단위 관람을 우선한다. 읽고 다음으로 넘기며 이미지와
   감상을 구분해 보존한다. 스토리 전용 화자/대사 추출기는 우선 보류하고, 자동 진행 장면과
   관리 중 짧은 NPC 통신은 별도로 누락 여부를 검증한다.

이 문서는 구현 승인 요청이나 기능 완료 보고가 아니다. 조사 결과를 다음 구현에서 사용할
범위·증거·검증 과제로 남긴 것이다. 원본 게임·세이브와 기존 입력 정지는 유지했다.
