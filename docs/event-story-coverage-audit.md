## 화자를 어떻게 구분하는가

1. **본편 일반 대화창:** `StoryDialogueUI.Speak`282111 부근에서
   `dialogueNameUI.text`에 표시 이름을 넣고 `dialogueDisplay`에 대사를 전달한다.
   이 두 최종 표시를 묶으면 화자와 발화를 구분할 수 있다. 이름이 빈 경우는 빈 상태로
   전달해야 하며 내부 캐릭터 ID로 채우지 않는다.
2. **튜토리얼 앤젤라:** `messageText`는 Text이지만 ANGELA 표시는 언어별 패널
   스프라이트 경로다(`LoadSprite`253195). 코드 클래스명이나 자산 파일명에서 이름을
   가져오면 화면 인식과 다른 정보 경로가 된다. 화면 이름/초상화 영역을 관람하고 이후
   확인한 외형과 이름을 플레이어 기억에서 연결하는 방식이 적합하다.
3. **관리 중 세피라 통신:** `ConversationUI`는 이름 Text가 아니라 초상화·프레임 색·
   본문으로 구분한다. 사망 등의 이벤트가 발생해도 음소거·보스·날짜 조건에 따라 통신이
   표시되지 않을 수 있다(SefiraConversationController272560–272578,272727–272734).
   따라서 내부 사건 콜백이나 enum을 그대로 알림·화자 이름으로 전달하면 안 된다.

초상화가 보이는 경우 익명 시각 식별자와 화면 영역을 제공할 수 있다. 식별자는 공개
외형의 연결을 돕는 용도이며 숨은 정체·변장·동일 인물 여부를 내부 ID로 확정하지 않는다.
표정·CG·배경·강조 연출은 여전히 영상 관람 대상이다. 게임기가 내적 감정이나 서사적
의미를 정답처럼 붙이지 않고 플레이어가 관찰과 기억으로 해석한다.

## 대사 원문을 곧바로 읽으면 안 되는 이유

`DialogueDisplay.ProcessText`294594–294621은 Text에 한 글자씩 추가한다. 화면에 나온
부분만 읽어야 한다. `SetText`294527–294586은 줄바꿈 계산 중 전체 문자열을 Text에
임시로 넣었다가 지우므로 setter 순간을 수집하면 아직 표시되지 않은 내용이 샐 수 있다.
최종 렌더 프레임의 표시 내용을 확인하는 방식이 필요하다.

`StoryUI.Command_speak`285309–285340은 타이핑이 끝나기 전에 전체 문장을 내부 로그와
로그 UI에 넣는다. `_speakLogs` 또는 비활성 UI 전체를 읽는 방식은 부적합하다. 게임의
대화 로그를 실제로 열었을 때 보이는 부분을 읽는 것은 별도의 정상 관람 경로다.

편지·내레이션·추가 대사는 각각 `diaglogueText`, `narDiagDisplay`, `exDiagText`를 쓰며
대화창 활성 상태에 따라 달라진다. 선택지는 `StorySelectionUI.ShowSelection`283417에서
순차로 표시되므로 전체 선택지 데이터 대신 실제 등장한 textUI만 전달해야 한다.

## 관람 경험 기록의 공백과 최소 보완 방향

현재 이력은 `Observer.cs:193–196`의 GameManager PLAYING·양수 timeScale 조건을 따른다.
이번 정지된 튜토리얼 대사는 버퍼에 저장되지 않았다. 별도 StorySceneController가
구동하는 스토리 장면도 이 조건을 성립시킨다는 보장이 없다(GameManager.Awake179692은
STOP으로 시작). 최신 PNG는 계속 볼 수 있으나, 지나간 대화가 자동으로 남지는 않는다.

**기존 움직임 버퍼의 정지 동결은 유지하고, 바뀐 표시만 기록하는 개수 제한 관람·알림
버퍼를 분리하는 것이 적합하다.** 반복되는 정지화면은 추가하지 않고 정지 중 새 대사·
팝업·선택지·창 열기 등 실제 표시 변화만 남긴다. 별도 시간 삭제 로직은 필요하지 않다.

제안 기록 단위는 관측 시각/프레임, 메시지 표시 회차 ID, 화면 출처, 실제 표시 이름 또는
미확인 화자, 표시된 본문, 초상화·대사·선택지의 화면 영역, 관련 이미지 참조다.
같은 문장이 다시 등장할 수 있으므로 텍스트 해시만으로 영구 중복 제거하면 안 된다.
전달 순번·누락 수·개수 상한을 명시하고 클라이언트가 읽은 위치를 이어갈 수 있어야 한다.
이 임시 관람 기록과 플레이어의 감상·추정·회고, 장기 Obsidian/Git 경험 노트는 구분한다.

우선순위는 다음과 같다.

1. 튜토리얼/스토리/NPC 메시지·선택지와 미션·시스템 로그의 최종 표시 추출, 화자 그룹화.
2. 정지 중에도 바뀐 표시를 보존하는 관람 이벤트 버퍼와 MCP 읽기, 장기 기록용 참조.
3. 방 위 작업 진행·결과 UI의 월드 가시성 검증, 정보창의 긴 본문·스크롤 범위 보완.
4. 실제 사망·퀘스트 전환·여러 NPC·내레이션·선택지·자동 진행의 엔지니어링 검증.

필수 검증은 가림/화면 밖/닫힌 UI에서 제외, 글자 표시 중 뒷부분 미노출, 화자 전환과
본문의 같은 프레임 연결, 초상화만 있는 화자, 반복 대사 구분, 정지 중 변화 보존,
선택지의 지연 등장, 버퍼 초과와 클라이언트 지연 시 명시적 누락, 씬 전환이다.
이번 점검은 이 보완 기능을 구현하거나 위 전체 런타임 검증을 수행한 결과가 아니다.
