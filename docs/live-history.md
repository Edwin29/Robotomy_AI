# 최근 관측 버퍼와 비동기 읽기

2026-10-18 구현. 스크래치형 실행기는 보류한다.

## 동작

게임 관측은 AI의 답변을 기다리지 않는다. 최신 UI·벡터는 약100ms 목표,
화면은 기존 약1초 주기를 유지한다. 새 이력은 게임 진행 중에만 추가한다.
원본 설치·세이브와 분리된 실행본 및 기존 가상 입력 경로를 사용한다.

버퍼는 `.robotomy/live/history/`에 있으며 기본값은 관측300개, PNG 최대30장이다.
슬롯을 순환 덮어써 오래된 항목을 자동 퇴출한다. 시간 기반 만료나 삭제 타이머는 없다.
게임 재실행 시 새 세션으로 초기화하며, 영구 경험 원장이나 Obsidian 노트는 지우지 않는다.

실행 전 환경변수 `ROBOTOMY_HISTORY_SAMPLES`(1..600, 기본300),
`ROBOTOMY_HISTORY_FRAMES`(1..60, 기본30)으로 개수를 설정할 수 있다.
화면은 원래 관측과 연결되므로 그 관측이 퇴출되면 화면도 제거한다. 화면 개수는 상한이며,
관측 한도를 너무 작게 설정하면 해당 화면 상한만큼 보존되지 않을 수 있다.

게임의 실제 진행 조건인 `GameManager.state == PLAYING`과 `Time.timeScale > 0`을 함께
확인한다. 튜토리얼에는 상태만 바꾸는 정지 경로가 있어 시간 배율만 보면 안 된다.
이 판정은 장치 내부에서만 사용한다. 숨은 정지 원인·보스 플래그는 전달하지 않는다.
[게임 파일 근거](history-pause-file-audit.md)를 참고한다.

일시정지 중에는 이력 추가를 멈추고 기존 내용은 유지한다. 정지 직전 캡처한 대기 작업이
완료될 수는 있다. 최신 상태·화면 조회는 계속 갱신되므로 정지 중 카메라나 메뉴 변화도 볼 수 있다.
입력 중지 파일 `control/PAUSED`는 게임 일시정지와 다른 기능이다.

## 읽기 도구

- `read_live_history(after_sequence=None, limit=10, session=None)`: 기본 최근10개를 시간순으로 반환. 커서를 지정하면 그 이후의 첫 N개. 최대50개.
- `view_live_history_frame(session, sequence)`: 해당 관측에 연결된 과거 화면1장과 촬영 시각 반환. 임의 파일 경로를 받지 않는다.
- 후속 조회에는 반환된 session을 넘겨 재실행 전후 자료가 섞이지 않게 한다.
- `historical: true`, `actionable: false`는 과거 자료라는 뜻이다. 과거 벡터를 현재 좌표로 사용하거나 이력으로 제어 view_id를 만들지 않는다.
- 순번 간격은 정지 중에도 최신 관측이 갱신되기 때문에 생길 수 있다. 순번 간격과 실제 슬롯 읽기 실패를 따로 보고한다.
- 퇴출·게시 경합·세션 변경·해시 불일치는 누락 또는 실패로 반환한다. 실패 시 최신 이미지로 대체하지 않는다.

이력 읽기는 기존 UI·오디오·벡터 허용 목록을 재사용한다. 내부 개체명·경로·타깃·진단
값을 응답에 추가하지 않는다. 읽기만으로 Obsidian 노트나 경험 원장을 생성하지 않는다.
중요한 경험으로 선택해 장기 기록하는 작업은 별도다.

## 병렬 처리와 비용

- 최신 파일 게시와 이력 저장은 각각 별도의 제한된 작업 스레드다.
- 이력 대기열은 최대16개, 페이로드 추정64MiB로 제한하고 과부하 때 오래된 대기 항목을 버린다. 누락 카운터를 제공한다.
- 최신 파일은 같은 경로의 미처리 갱신을 최신 값으로 합쳐 오래된 값의 적체를 줄인다.
- MCP 입력 완료 대기는 작업 스레드에서 수행한다. 같은 서버에서 최신 관측·과거 자료를 읽는 이벤트 루프를 막지 않는다.
- Unity 객체 읽기와 가시성 판정은 메인 스레드에서 수행하고, 작업 스레드에는 문자열과 이미 인코딩된 픽셀 바이트만 전달한다.
- 이력 초기화 실패 시 최신 관측은 계속된다. 게시 전에 슬롯 세대를 무효화하고, 읽을 때 세션·순번·프레임·이미지 해시를 확인한다.

GPU 캡처, PNG 압축의 외부 스레드 이동, 고속 영상 코덱은 이번 구현에 포함하지 않았다.
현재 ReadPixels/EncodeToPNG 및 최신 프레임 해시 계산의 메인 스레드 비용은 남아 있다.
이력 추가만으로 LLM의 판단 속도가 빨라지거나 후반 실시간 대응이 검증된 것은 아니다.

## 검증

자동 검증은 실제 C# 저장 코드를 별도 임시 폴더에서 실행한다. 개수 초과, 순번 공백,
화면 슬롯 교체, 시간 경과에 따른 무삭제, 파일 공유 오류, 재시작 정리를 검사한다.
Python은 과거 관측 검증·숨은 필드 제거·세션/해시 경합을 검사한다. MCP는 느린 입력
대기 중 별도 읽기가 완료되는지 확인한다. 실제 게임 정지/재개 검증과 합성 검증을 구분한다.

실행 검증 결과는 [인계 기록](handoff.md)과 `.robotomy/live/verification/history/`에 기록한다.
