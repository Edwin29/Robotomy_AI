# 입력 대상 검증 예약 — 소스 구현, 실행 중 게임에는 미적용

## 신규 동작과 적용 경계

관찰 모듈이 `input_verified=true`로 제공한 버튼 중심 `hit_x/hit_y`를 클릭하는 예약은
다른 메뉴/텍스트가 바뀌어도 같은 대상 ID·위치·크기와 클릭 가능 판정이 유지되면 실행한다.
대상이 사라지거나 가려지거나 비활성화되거나 이동하면 `target_invalid`로 중단한다.
Unity EventSystem의 읽기 전용 RaycastAll 결과의 최상위 클릭 수신자가 해당 Button인지
확인한다. 기존 최종 표시 가림 필터도 통과해야 하며 내부 게임 상태/이름으로 추론하지 않는다.
확인하지 않은 좌표, 키/드래그 등은 기존 전체 UI 변화 중단을 유지한다.
프로세스/씬/해상도 변경, 취소, 만료, 운영자 Stop, 신선한 관찰 부재도 계속 중단한다.

현재 구현의 보수적 제한: 버튼 중심만 검증하며 임의 좌표로 자동 보정하지 않는다.
기존 가림 검사에서 확인하지 못하는 커스텀 UI는 계속 중단한다. 2배속 버튼의 실제
지원 여부는 새 DLL 적용 후 화면 대조로 확인해야 한다. 관찰과 입력 사이의 변화까지
원자적으로 막는 기능은 아니며 실행기 기존 검사도 함께 유지한다.

이번 변경은 별도 게시 checkout에만 저장했다. 진행 중 플레이의 MCP resident 검사에
영향을 주지 않도록 운영 checkout의 input_sequence.py를 변경하지 않았다.
플레이 종료 후 소스 반영, 격리 런타임 Observer 재빌드/무결성 갱신, 게임과 MCP의
정상 재시작이 필요하다. 실행 중 DLL 교체나 프로세스 종료는 하지 않았다.

검증: 독립 DLL 컴파일 성공. 예약 테스트에서 메뉴 변화 뒤 유효 대상 계속 실행,
대상 제거/비활성/가림/이동/교체 중단, 기존 취소와 장면 전환 중단을 확인했다.
실게임의 2배속 전환은 진행 중 플레이 보호 때문에 미시험이다.

# 짧은 비동기 입력 예약 (서버 연결 완료)

2026-10-18 플레이 종료 후 서버 연결을 활성화했다. 새 MCP 연결에서 세 도구가 노출된다.
기존 Codex 채팅의 구형 MCP는 재연결이 필요하다. Unity DLL/게임 프로세스 재시작은 없다.
pending-input-sequence.patch는 최초 연결안의 역사적 자료이며 다시 적용하지 않는다.
최종 구현은 생성된 실행기의 코드 갱신을 유지하도록 executor를 주입하고, 단일 입력도
동일 잠금으로 보호한다. 예약 중 코드 갱신은 막고 상태조회/취소는 계속 허용한다.

## 플레이어 사용

1. capture_live_control 및 필요시 화면 확인.
2. 같은 view_id로 prepare_live_action을 1~5회 호출해 이미 결정한 입력 ID를 준비.
3. submit_input_sequence(decision_ids)를 한 번 호출. 수락 ID가 즉시 반환된다.
4. 읽기 관찰 도구를 쓰거나 다음 판단을 수행하고 input_sequence_status로 확인.
5. 필요시 cancel_input_sequence. 실행 중 동작은 끝나고 나머지 입력은 취소된다.

취소는 이미 전달한 행동을 취소/되돌리지 않는다. 현재 동작은 최대 3초이며 응답 대기가
추가될 수 있다. 10초 이후 새 단계를 보내지 않지만 이미 진행 중인 무결성 검사/응답 대기의
완료까지 총 시간은 더 걸릴 수 있다. 프로세스 강제 종료 후 자동 재개하지 않는다.

입력 개수 최대5, 입력 지속시간 합계5초. 루프/조건/자동 재계획 없음. 기존 관찰 만료,
운영자 Stop, 프로세스/장면/크기 검증과 입력 영수증 확인을 그대로 거친다.
공개 UI 텍스트나 버튼 목록이 바뀌면 다음 단계를 멈춘다. 이는 보수적 검사라 숫자 변화에도
멈출 수 있다. 픽셀만 바뀌는 연출/카메라 이동/대상 이동까지 판별하는 장치는 아니다.
새 캡처로 view_id가 바뀌어도 기존 준비 입력이 거절되므로 도중 관찰에는 observe_live 또는
view_live_frame을 사용한다. 화면 전환 검사는 단계 사이이며 입력 도중의 원자적 보장은 아니다.

단일 입력에도 동일한 파일 잠금을 적용하는 연결 패치를 반드시 함께 적용한다. 서로 다른
MCP의 입력은 뒤섞지 않고 거절한다. 단, 구형 MCP는 잠금을 모르므로 활성화 시 모든
구형 플레이어 MCP를 종료해야 한다. 예약 실행 중 코드 재로딩/코드 수정은 하지 않는다.
게임 창/OS 마우스/NVIDIA는 조작하지 않는다.

예약 제출/종료와 기존 입력 영수증은 경험 원장에 기록한다. 입력 완료는 게임 목표 달성의
증명이 아니므로 후속 관찰이 필요하다. 모델이 실제로 도구 실행 중 계속 추론하는지는
클라이언트 호출 방식에 달려 있으며, 서버의 비동기 반환만으로 보장하지 않는다.

검증: 임시 폴더에서 순서, 비차단 반환, 다른 입력 배제, 취소, UI/장면 변화, unknown,
관찰 실패 시 영수증 보존, 코드 재로딩 중 취소 가능 여부를 확인했다.
실제 게임 PID37320의 본편1일차 결과 화면에서 새 stdio MCP로 다음을 확인했다.
- 포인터 이동3개 순서대로 완료; submit 응답 약15ms (한 번의 측정).
- 이동 도중 취소: 첫 입력만 완료하고 두 번째 입력은 전송되지 않음.
- 1648x927 창을 잠시 1600x900으로 변경: Unity가 Scene or resolution changed during gesture로
  입력을 해제하고 unknown 영수증을 반환; 예약은 input_not_confirmed로 나머지를 중단.
- 원래 창 크기와 가상 포인터(825,56)를 복원. 다음 날/재시도 버튼 클릭 없음.
실제 다른 장면으로 진행하는 시험은 세이브/진도 보존을 위해 하지 않았다. 크기 변경 중단과
장면 ID 전환 모의 테스트의 증거를 구분한다. 픽셀 전용 변화는 여전히 보장하지 않는다.
