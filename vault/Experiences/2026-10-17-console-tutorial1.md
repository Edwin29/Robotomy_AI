# 게임기만 사용한 튜토리얼 1 시험

2026-10-17 22:35:27–22:47:34 KST, 약12분. 게임기의 캡처·표시 문구·익명 소리 이벤트와
가상 입력만 사용했다. 게임 내부 분석 자료를 플레이 중 새로 읽지 않았고 사람에게 조작을 요청하지 않았다.
이전 플레이/개발 지식이 있는 같은 모델의 시험이므로 무지식 첫 플레이 실험은 아니다.
개발용 가림·소리 진단은 다른 프로세스에서 끝낸 뒤 새로 실행했다.

## 실제 한 일과 결과

- D/A 각각1200ms로 화면 이동, 휠 확대, 화살표가 가리킨 직원 선택.
- 데봉의 표시 정보를 읽고 본능 작업 지시. 결과 에너지9/20 확인.
- 직원 선택→격리실 우클릭→통찰 작업. 완료 후19/20 확인.
- 고유 PE-Box로 기본 정보·관리법·네 작업 선호도·탈출 정보 개방.
- E.G.O 무기와 방어구 각각1개 제조, 환상체 기록 열람.
- 회복된 직원과 애착 성공률 매우높음을 확인하고 세 번째 작업 지시.
- 20/20 달성 후 업무 종료. 관리자 교육 완료, S등급, 생존1·사망0·승급1·보상3 확인.
- 결과 안내를 읽고 다음 튜토리얼 진행은 거절해 타이틀로 복귀. 입력 중지.

54개 실제 입력, 64개 저장 관찰. 각 행동의 이유와 예상 결과를 먼저 기록했고 후속 화면으로
결과를 평가했다. 입력 전송 receipt만으로 완료를 판정하지 않았다.

## 이 회차에서 배운 것

작업을 지시하자 즉시 결과가 나오지 않았다. 직원이 복도를 이동하고 격리실에 들어간 뒤
생산이 진행됐다. 첫 작업의 에너지 증가를 확인한 후에야 결과로 기록했다.
직원 정보창의 최대 체력32와 작업 선택창의 현재 체력30/32는 다른 표시다.
최대값이 그대로라고 현재 체력이 회복됐다고 해석하면 안 된다.

개방 전 작업 메뉴에는 Unknown/측정불가가 있었다. 기본 정보와 선호도를 열자 이름·위험등급·
공격 수치·성공률·작업시간이 나타났다. 이 교육용 오뚜기 토끼에서 본능·통찰은 높음,
애착은 매우높음, 억압은 보통이었다. 화면의 관리법에는 억압 완료 시 클리포트 카운터가
감소한다고 적혀 있었다. 따라서 세 번째는 애착을 선택했다. 다른 환상체에 일반화하지 않는다.

작업 후 재작업 대기시간과 부서 중앙의 회복이 있었다. 튜토리얼이 설명 중 시간을 멈추므로
설명을 넘기지 않고 기다리기만 하면 작업도 진행하지 않을 수 있었다.
관찰로 얻은 선호도뿐 아니라 화면의 화살표·대화창·직원 위치가 진행에 필요했다.

## 시행착오와 장치의 한계

1. 첫 설명 클릭1초 후 캡처에는 이전 설명이 남았다. 곧바로 다시 누르지 않고 재관찰하자 전환이 확인됐다.
2. 최신 관찰을 얻지 못해 행동 준비가 두 번 거부됐다. 입력 전 오류였고 새 화면을 확인한 후 새 결정을 만들었다.
   개발자가 시험 이후 읽기·파일 게시 처리를 보완했다. 원래 오류 기록은 성공으로 고치지 않는다.
3. 도감 관리법은 상단 설명창에, 선호도는 툴팁에 가려졌다. 가려진 부분은 읽지 않았다고 기록했다.
   포인터가 다른 위치로 이동하거나 설명 단계가 바뀐 뒤 보이는 내용을 확인했다.
4. 긴 환상체 기록은 픽셀로 보였지만 구조화 목록에는 없었다. 비전 캡처가 있어 계속 진행할 수 있었다.
5. 다음날 버튼 뒤에 두 번의 확인 절차가 있었다. 화면을 보고 각각 처리해 완료와 전환을 구분했다.

소리 이벤트는 익명 토큰이다. 메뉴 클릭·제조·폭주 경보 전후 이벤트를 관측했지만
파형을 듣거나 모든 토큰의 의미를 학습했다고 주장하지 않는다.
이 경험은 느린 안내형 튜토리얼의 조작 가능성을 보여주며 후반 전투 반응성을 증명하지 않는다.
