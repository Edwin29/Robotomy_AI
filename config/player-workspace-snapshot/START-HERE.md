# 다음 플레이어 시작하기

이 폴더에서 새 Codex 작업을 열고 `robotomy_player` MCP가 연결되는지 확인한다.
개발 작업의 대화를 복제하지 말고 RUN-PROMPT.md의 요청으로 시작한다. 처음 폴더를 열 때 Codex의
프로젝트 신뢰/도구 연결이 필요할 수 있다. 현재 폴더가 로컬 플러그인 방식이라면 Plugins의 Lobotomy Local 소스에서
Lobotomy Player 설치 상태를 확인한다. 최초 전환은 기존 MCP의 재연결이 필요하며 앱 재시작이
필요할 수 있다. 게임 창은 그대로 둔다. 다른 플레이어 MCP 호스트를 동시에 실행하지 않는다.

## 운영자

1. `Ready-Player.cmd`를 실행한다. 원본 저장/설정과 분리 런타임의 무결성, 관찰/가상 입력을
   검사한다. 게임이 꺼졌으면 검증된 분리 실행본을 시작하고 입력을 허용한다. 스스로 플레이하지 않는다.
2. http://127.0.0.1:8765/ 에서 화면과 선택 이유를 관찰한다. 이 페이지는 관찰용이다.
3. RUN-PROMPT.md의 요청을 새 플레이어에게 보낸다.
4. 입력을 중단하려면 `Stop-Player.cmd`. 이것은 AI 입력 중지이며 게임 시간 자체의 일시정지는 아니다.

이미 게임이 켜진 상태에서 재시작/세이브 초기화를 수행하지 않는다. 원본 무결성이 달라졌거나
미해결 명령이 있으면 준비가 중단된다. 이 경우 개발 담당자가 원인을 점검해야 한다.

녹화용 Lobotomy_Observer 게임 창은 테두리로 크기를 조절할 수 있다. 조절을 마치면16:9로
맞춰지며 최대화 버튼은 모니터 안에 들어가는 가장 큰16:9 창으로 맞춘다(최대1920×1080).
게임의 캡처 부하를 제한하기 위한 상한이다. AI가 조작 중일 때
크기를 바꾸면 이전 좌표의 입력이 취소될 수 있으므로 녹화 크기를 먼저 정한 뒤 플레이를 시작한다.

## 실행 요청

[RUN-PROMPT.md](RUN-PROMPT.md)의 짧은 요청을 그대로 새 플레이어에게 전달한다.
다음 실행에서는 이 파일의 진행 범위와 종료 조건만 바꾸면 된다. 다른 규칙은 반복하지 않는다.

## 문서 위치

AGENTS.md는 프로젝트 목적·정보 경계·게임기 사용을 담당한다. 역할의 관점은
Player-Persona.md, 기록 절차는 Recording-Rules.md, 선택적 회고 질문은
Day-Review-Template.md에 있다. 플레이어는 read_player_guide로 이 네 문서를 읽는다.
현재의 취향·믿음은 read_player_memory로 읽으며 최초 페르소나와 구분한다.

## 비용과 기록

로컬 게임기와 기록은 별도 모델 API를 호출하지 않는다. 플레이어는 사용 중인 Codex 구독 환경에서
연결하며 구독 사용량 제한은 적용된다. 기록은 중앙 경험 저장소에 남고 `read_player_memory`,
`read_experience_events`, `export_player_experience`로 다른 모델에 전달할 수 있다.
이 문서와 안내 폴더는 OS 보안 격리를 제공하지 않는다.

프로젝트별 MCP 설정은 신뢰된 프로젝트에 적용된다.
[Codex 공식 MCP 설정 문서](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)

## 코드 재로딩

연결이 새 호스트로 전환된 뒤에는 관찰·입력 구현 수정이 다음 도구 호출에 자동 반영된다.
`player_runtime_status`와 `reload_player_code`로 확인한다. 저장 구조/전원/호스트/도구 스키마 변경은
MCP 재연결이 필요하며 게임 DLL 변경은 별도 유지보수가 필요하다. 자세한 안내는 PLUGIN-RELOAD.md.
